# 发布打包：引擎怎么随输入法发布

原先的装法是：`scripts/install.sh` 只装壳，自带的引擎从仓库复制进 `~/.luoke/ime/engines/`，靠这台机器上的 Homebrew（librime）和 Xcode 命令行工具（`python3`）；干净的 Mac 上这些都没有。这一页是发布时引擎要带什么、放在哪、由谁装（和 luoke-core 商定，luoke-core V1 §10 第 5 项）。

**已做**：`scripts/bundle-engines.sh` 组装、`install.sh` 由内向外签名、公证（Accepted，连同用私有库的小鹤、全拼一起），58 MB；个人化组件跑在主控的 Python 3.12 上。luoke-core 已把 Python 的约定写进它的注册页和 V1 §8。


## 引擎在运行时要什么

| 引擎 | 程序 | 依赖 | 大小 |
|---|---|---|---|
| 小鹤、全拼（同一份代码） | Swift 主程序（用系统自带的 Swift 运行库）、`rime_helper`（C） | 苹果私有库 libmecabra（系统自带）；librime + librime-lua + 9 个依赖的动态库（现在链 Homebrew 的路径）；雾凇词库（YAML，GPL-3.0） | 程序不到 1 MB；动态库约 12 MB；雾凇 48 MB；RIME 第一次运行时编出的词典 73 MB（在数据目录里） |
| 个人化组件 | `personal.py`（只用标准库）、自带的 luoke_mem | **一个 Python**：现在 `engine.json` 写的是 `python3`，走 `/usr/bin/python3`；干净的 Mac 上它只是个占位，一调用就弹窗要用户装 Xcode 命令行工具 | 脚本不到 1 MB；Python 见下 |

本机打分（`scorer.py`、MLX）不随发布：发布版只经主控打分。`bundle-engines.sh` 不带 `scorer.py`，发布用的 `engine.json` 去掉 GPU 权限和模型的选项；个人化组件找不到 `scorer.py` 时选项 `scorer` 写什么都只经主控。自带的 luoke_mem 只带 `__init__.py`、`memory.py`、`sensitive.py`（learn、hub、ui 是螺壳记忆 app 自己的，和 luoke-mem 商定）。

## 定下的

1. 自带的引擎**放进 LuokeIME.app**（下面的 A）。
2. 个人化组件**用主控里的 Python**（下面的 d）：主控是装输入法的那一方，一定在；个人化组件只用标准库，主控带的 3.12 够用；沙盒本来就放行读文件和启动程序，不用放宽。路径要 luoke-core 当约定保证，正在商定。

## 当时的选项

### 1. 引擎放在哪、由谁装

- **A. 放进 LuokeIME.app**（推荐）：`Contents/Resources/engines/{xiaohe,quanpin,personal}`，和壳一起签名、公证。壳从包里直接运行它们（只读；沙盒本来就只放行读引擎文件夹），用户自己装的第三方引擎照旧放 `~/.luoke/ime/engines/`。主控只装 LuokeIME.app（现有约定，V1 §8），发布清单里不必多一项；壳和自带引擎的版本永远对得上，一次公证。数据目录不变（`~/.luoke/ime/data/<标识>`）。
- **B. 单独的引擎包**：主控按发布清单下载、解到 `~/.luoke/ime/engines/`。好处是引擎能单独更新、私有库那部分和壳分开公证；代价是主控要多管一类东西（下载、校验、替换正在跑的引擎）、壳和引擎的版本要对、多一次公证。

私有库的风险（`docs/再分发与许可.md`）：苹果吊销某一份的公证票据时，A 会让整个输入法打不开，B 只影响引擎包。但这份风险本来就低，而且吊销证书时两种做法都一样受影响；输入法已经和主控、邮件助手分开签了。所以推荐 A。

壳要改的（A）：找引擎时先看包里的、再看 `~/.luoke/ime/engines/`（同一个标识以用户装的为准，方便开发）；包里的引擎不监视文件改动。

### 2. 个人化组件用哪个 Python

- **a. 自带一份精简的 python-build-standalone**（推荐）：和主控、记忆用的同一个发行版（3.12），去掉 tkinter、idlelib、ensurepip、test、`__pycache__` 和 site-packages，约 40 MB（螺壳记忆.app 里完整的一份 86 MB）。放在个人化组件的文件夹里，沙盒照旧只放行读这个文件夹；签名时 Python 的二进制要带 hardened runtime 和它需要的 entitlements（luoke-core 的 `tools/entitlements-python.plist` 可以照用）。
- **b. 借螺壳记忆.app 里的 Python 和 luoke_mem**：不重复带，luoke_mem 永远和写记忆的那一份同版本。代价是输入法依赖记忆配件包里的路径布局（要 luoke-mem 和 luoke-core 当作约定保证），沙盒要放行读另一个 app 的内容，记忆配件升级可能连带影响输入法；没装记忆配件（用户没同意记忆时也一样要用 Python 转打分）就什么都没有。
- c. 个人化组件改用 Swift：luoke_mem 是 Python，写记忆的规则（敏感三类、整段不记）要在两种语言里各维护一份，不考虑。
- **d. 用主控里的 Python**（选了这个）：`螺壳主控.app/Contents/Resources/python/bin/python3`（luoke-core V1 §8 写明的布局）。壳按 bundle id `ai.luoke.core` 找到主控，把它交给个人化组件；找不到主控时退回 PATH 里的 `python3`（开发机）。没装主控就没有个人化组件（不写记忆、没有重排和联想），但正式的装法里输入法就是主控装的；打字本身不受影响。luoke_mem 照旧自带在组件文件夹里。运行时设 `PYTHONDONTWRITEBYTECODE=1`（不往主控包里写字节码，写了会弄坏签名）。

## 其余要做的（不用定，照做）

- ~~`rime_helper` 带上 librime、librime-lua 和 9 个依赖~~ 改成从源码编：Homebrew 的库都是按本机系统编的（在 macOS 27 上编就要求 27），装到 26 上加载不了。`scripts/build-librime.sh` 照鼠须管的做法编出一个部署目标 macOS 14 的 librime.1.dylib（依赖静态链进去、lua 插件合并进去），包里只有这一个动态库；所有程序都按 macOS 14 编，`install.sh` 组装后用 luoke-core 的 `tools/minos_check.py` 核对。许可汇成 `THIRD_PARTY_NOTICES`，雾凇附 GPL 全文和上游提交号（`docs/再分发与许可.md`）。
- RIME 的词典第一次运行时编（M5 Max 约 15 秒，M1 要几分钟；这期间只出苹果的候选），不预先编好随包带（多 73 MB）。
- `scripts/install.sh` 换成发布用的打包脚本：编译 → 组装引擎 → 由内向外签名（所有 Mach-O）→ 公证 → staple；产物交给主控的发布脚本，评测照旧用 `bench.py --result`。
- 输入法的大小：壳 2.5 MB + 引擎和雾凇约 60 MB + Python 约 40 MB，约 100 MB（压缩后更小）。
