# 螺壳输入法 设计文档

螺壳输入法是一个极简的 macOS 输入法，也就是下文说的"壳"：它只捕捉按键、显示候选、上屏，出什么候选全部交给引擎。引擎是任何人（或者他的 agent）都能随手写的独立程序，可以是查表、RIME、本地模型，也可以是语音、图片识字。

- 术语：[CONTEXT.md](../CONTEXT.md)。本文用到的加粗词都按那里的定义。
- 引擎协议的字段和示例：[引擎协议.md](引擎协议.md)。
- 怎么写一个引擎：[写引擎.md](写引擎.md)。
- 重要取舍：[adr/](adr/)。

## 目标与非目标

**目标**

1. 写一个能用的引擎，门槛低到一个 agent 读完一页说明就能写对：最小引擎十几行，无状态，任何语言。
2. 所有引擎手感一致，像系统输入法：按键规则、候选窗、标点规则都由壳统一管。
3. 兼容性靠自动化测试矩阵磨出来，而不是靠多年的用户反馈。
4. 引擎是潜在的键盘记录器，所以壳要保证：引擎拿不到它没声明需要的东西，也做不了它没声明的事。

**非目标**

- 壳不懂任何语言规则，不内置词库、模型、学习逻辑。模型由螺壳主控提供（主控上线前在引擎内部），个人化由个人化组件统一做（见"个人化与联想"）。
- 不追求 RIME 那样的可配置程度：壳的设置项只有几个，键位只有三个开关。
- 不上 App Store（壳要用沙盒启动任意子进程）。
- 第一版只考虑简体中文引擎。

## 总体结构

```
┌──────────────── 螺壳.app（输入法进程）────────────────┐
│  macOS 外壳（薄）                                     │
│   系统按键事件 → 状态机；显示串/候选窗/上屏 ← 状态机    │
│  ───────────────────────────────────────────────────  │
│  状态机（平台无关）            引擎宿主（平台无关）       │
│   输入串、已选部分、键位规则 ⇄  启动/重启/停用引擎       │
│   先快后好、收尾上屏、反馈       沙盒、标准输入输出       │
└──────────────────────────────────┬────────────────────┘
                                   │ 每行一个 JSON
              ┌────────────────────┴───────────────────────────┐
              │ 当前引擎（打字）  快捷键引擎 × n  个人化组件     │  ← 各自在 Seatbelt 沙盒里
              └────────────────────────────────────────────────┘

luoke-ime（命令行版）= 同一个状态机 + 同一个引擎宿主 + 终端界面
```

壳分两层（ADR 0007）。平台无关的状态机和引擎宿主是一个 Swift 包，只依赖 Foundation；macOS 外壳只负责把系统事件喂进去、把结果画出来。命令行版直接复用前两者，所以它和真实输入法行为完全一致。新的按键行为只能写进状态机，不能写在 macOS 那层。

状态机里的时间（50 ms、150 ms 等）通过可注入的时钟取得，测试时可以精确控制。

## 壳的行为

### 状态

| 状态 | 含义 |
|---|---|
| 空闲 | 没有输入串，也没有已选部分 |
| 输入中 | 有输入串或已选部分，光标处显示"已选部分 + 显示串" |
| 快捷键会话 | 某个快捷键引擎接管了光标处 |

**英文模式**是独立于上面三种状态的开关：开着时所有按键放行（开了"中英文之间加空格"时，汉字后面的第一个字母除外，见下文）。单按 Shift 切换：按下时没有别的修饰键，按下到松开之间也没有按别的键、别的修饰键或鼠标（⇧ 加点击扩选不算）。按应用记住：同一个应用里换输入框不变，换到别的应用时用那个应用上次的状态，第一次进入时用它的默认值（设了"默认英文"的应用是英文，其余是中文）；只记在内存里，螺壳重启后回到默认值；Caps Lock 开着时也按英文模式处理；系统设置里开了"使用大写锁定键切换'ABC'输入法"时，短按 Caps Lock 由系统切到 ABC、再按切回来，和系统拼音一样（Info.plist 声明 `TICapsLockLanguageSwitchCapable`，系统自带的泰米尔输入法也是这么声明的；luokelabs/luoke-ime#5）。当前引擎没在运行（启动中、重启中、停用）时，空闲时的表现和英文模式一样；正在输入时见[出问题时](#出问题时)。

### 键位

默认键位，设置里只开放三个开关（翻页键、Shift 切中英、切换引擎快捷键）。

**空闲时**

| 按键 | 行为 |
|---|---|
| 输入键 | 进入输入中，发出询问 |
| 标点表里的符号 | 上屏对应文字（数字后的 `.` `:` 保持半角：3.14、12:30；数字后的 `,` 先挂在光标处、看下一个键：接数字是半角 1,000，接别的是全角「27，所以」，退格就不要了；成对符号交替；`{` `}` 默认上屏「」，和系统简体拼音一样（`[` `]` 是【】），设置里能关，开着时不管引擎的标点表） |
| 退格 | 放行；若紧跟在一次上屏之后，计入反馈 |
| 其他 | 放行 |

**输入中**

| 按键 | 行为 |
|---|---|
| 输入键 | 追加到输入串，发出询问 |
| 1–9 | 选当前页第几个；那个位置没有候选就忽略。还没有任何答复时先等到第一份答复（最多到判定卡死的 1 秒，卡死了就按原始字母收尾、数字照原样交给应用），再像空格一样等补发；候选还没画出来（50 ms 内）时这一下只把它画出来，不选 |
| 0 | 忽略 |
| 空格 | 选高亮的候选；一份答复都还没有时先等到第一份（最多到判定卡死的 1 秒，不上屏原样拼音，luokelabs/luoke-ime#11）；补发还在路上时最多再等 150 ms；一个候选都没有时照原样上屏字母 |
| ← →、Tab | 移动高亮（竖排时为 ↑ ↓；竖排时 ← → 和 Tab 翻页） |
| `-` `=`、↑ ↓、PageUp PageDown | 翻页（`-` `=` 可改成 `,` `.`，此时这两个键输入中不再作标点）。第一页按 `-`（没有上一页可翻）：拼音串照原样字母上屏、再接 `-`，好打 luoke-ime、gpt-4 这类词（luokelabs/luoke-ime#17） |
| 退格 | 删输入串最后一个键；输入串已空时撤销最后一段已选部分，恢复它的键；全空则回到空闲 |
| Esc | 丢弃输入串和已选部分 |
| 回车 | 上屏已选部分 + 剩余原始字母 |
| Shift+⌫ | 对高亮候选发出"忘掉" |
| `[` `]` | 以词定字：`[` 只要高亮候选的第一个字、`]` 只要最后一个字，当作选了它（剩下的键接着打；一份答复都还没有时先等到第一份，没有候选就照常当标点）。上屏反馈里这一段带 `char`，引擎不拿它学 |
| 标点表里的符号 | 收尾上屏，再上屏标点 |
| 带 ⌘ ⌃ ⌥ 的组合键、Shift+字母 | 收尾上屏，再放行这个键；例外：引擎在 `input_keys` 里声明了大写字母时，组字开头（或大写开头的组字里）的大写字母进组字，用来打英文（GitHub） |
| 单按 Shift | 上屏已选部分 + 剩余原始字母，进入英文模式（打了个英文词，按 Shift 确认） |

选中一个候选后：若它用掉了全部剩余输入串，就把已选部分连同它一起上屏；否则它成为已选部分的新一段，壳拿剩下的键重新询问（ADR 0001）。

**快捷键会话中**：Esc 取消，什么都不上屏；按别的键时先上屏最近一次 `show` 的文字，再正常处理这个键。

### 收尾上屏

按标点、切走（点了别处、换了应用）、触发快捷键引擎时，壳要一次把正在输入的内容全部上屏：先选高亮的候选；若还剩输入串，就用最新答复的首选接着选，直到用完；拿不到答复的部分按原始字母上屏。

切走时系统要求立刻交出结果，壳不能再等答复，所以只用手上已有的答复。这次上屏照常作为反馈报告，带 `auto: true`，引擎可以据此不拿它学习。

### 先快后好的显示规则

引擎对一次询问可以先答复一份快的，再补发更好的（ADR 0003）。壳的规则：

1. 发出询问后、新答复画出来之前：光标处显示上一次的显示串接上新敲的键（没有就显示原始输入串）；候选窗继续显示上一份候选，不清空，免得每敲一个键闪一下。一段输入的第一个键之前没有候选窗。
2. 50 ms 内收到的最后一份答复直接画出来；若 50 ms 到了还在等补发，先画手上的这份。
3. 补发到了就整体替换；但用户已经移动高亮或翻页，就不再替换，免得在手指底下换词。
4. 按空格（数字、标点收尾同样）时，一份答复都还没有就先等到第一份，最多等到判定卡死（1 秒）；若当前答复标了 `more: true`，最多再等 150 ms；等到就用新的，等不到就用现有的。
5. 不是最新询问的答复一律丢弃。
6. 轻提示用 ✦，意思始终是"慢的那一路（比如模型）"；只有打错纠正另用 ✎：画出来的这份标了 `more` 时，候选条末尾有个慢慢浮现、缓缓呼吸的 ✦（补发很快就到时几乎看不见）；补发换掉了已经看到的首选时，新首选淡入约 0.1 秒；引擎在注释里写 ✦ 标出被它改过的候选（小鹤、全拼引擎这样做：模型按前文换了首选），没改就什么都不留；双拼读不通时**打错纠正**纠出的整句标 ✎，看得出是按的键被改了，不是换了词。

### 前文

- 在每次进入输入中、以及快捷键引擎触发时，壳读一次同一输入框里光标前的文字，最多读引擎声明的字数；声明为 0 就根本不读（个人化组件和"中英文之间加空格"要的，按其中最多的读，各取各的）。
- 已选部分接在前文末尾一起发给引擎。
- 读不到时（应用不提供），用壳在这个输入框里最近上屏和放行的文字代替；输入框失去焦点时清空，不同输入框、不同应用之间互不串用。
- 系统处于安全输入状态（比如密码框）时一律不读。
- 当前应用的 bundle id 只在引擎声明 `app: true` 时给。

### 中英文之间加空格

设置里的开关（菜单"中英文之间加空格"），默认关。和"数字后保持半角"一样是壳的排版规则：只看字的类别，不懂语言，所有引擎和英文模式下都一致。

- 汉字（和假名）与半角字母、数字挨着时，中间补一个半角空格；挨着标点或已经有空格时不加。上屏的一段字里面的交界也照这样补（语音一次上屏一整句，比如「把PR发到GitHub上」上屏成 `把 PR 发到 GitHub 上`），快捷键引擎的显示串也一样显示。
- **上屏时**看光标前的那个字（进入输入中时读到的前文最后一个字）：`iPhone` 后面上屏"很好"成了 `iPhone 很好`，"你好"后面上屏英文候选或回车上屏原始字母也一样。
- **汉字后面直接敲字母、数字**（英文模式下，或中文模式下的数字）：壳把这个键改成"空格 + 这个字"上屏，之后的键照常放行。这里只信壳自己在这个输入框里上屏、放行过的字（光标动过、点过鼠标就不算了），读到的前文不算：在终端的 vim 里，前文是中文也不该往命令前面插空格。
- 用户删掉了自动加的空格，紧接着那一下不再加，之后照常。
- 反馈和转给个人化组件的上屏里，`text` 是引擎给的字，不含自动加的空格。

### 反馈

只有三种原始事件，只发给声明了 `feedback: true` 的引擎（字段见协议）。安全输入、暂停记录、"不记录"的应用里一律不发：哪里都不留痕迹，引擎在这些应用里学不到新词（ARCHITECTURE §4）。

1. **上屏**：每段键和字、选的第几个、当时的首选、整句、前文、是否切走时自动上屏。
2. **上屏后的退格**：紧接着一次上屏，连续按了几次退格（不带修饰键的；⌥⌫、⌘⌫ 算别的键）。遇到别的键、换输入框、换应用，或 5 秒内没再按退格时结束计数。输入法能收到当前应用里的所有按键，所以这一条在微信、浏览器里一样有效，不需要辅助功能权限。
3. **忘掉**：候选窗里高亮一个候选按 Shift+⌫。

壳不判断这些事件意味着什么，也不报告其他任何非输入时的按键。

### 候选窗

- 壳自己画，外观仿系统简体拼音：毛玻璃背景、数字编号、首选高亮、跟随深浅色模式。
- 用户设置：横排或竖排（默认横排）、每页 1–9 个（默认 9）、字号。所有引擎统一，引擎改不了。
- 引擎唯一能影响外观的是候选的注释，以灰色小字显示在候选后面。
- 位置在光标下方；拿不到光标位置时放在鼠标处。只有当前输入框画候选窗。

### 应用设置

壳按应用（bundle id，不按显示名）记下覆盖全局的几项，只归壳管，引擎不知道（ADR 0011）。没写的项**跟随全局**，按项继承：覆盖一项不冻结别的项；"恢复跟随全局"整条删掉。

- **默认输入模式**：跟随全局／中文／英文。
- **拼音显示位置**：跟随全局／输入框里／候选窗口里。候选窗口里：光标处什么也不放，显示串改在候选窗顶部显示，直到上屏，用于处理不好内嵌文字的网页编辑器、终端、远程桌面、游戏。
- **联想**：跟随全局／开／关（装了个人化组件时才有）。关：上屏后不问联想，Tab 一直交给应用。终端（Terminal、iTerm2、Ghostty、Warp 等，`ShellConfig.terminals`）默认关：终端不把 Tab 交给输入法，联想选不上，按 Tab 反而触发 shell 的补全（实测后定）；应用设置里能打开。
- **记忆记录**：遵循全局／禁止记录（装了个人化组件时才有）。只能进一步禁止，不能绕过全局的未同意或暂停。

壳自带一份已知问题应用的名单（随跨应用测试矩阵补充，目前还是空的：终端里默认英文不合适，测过的应用都能内嵌），用户的设置优先。菜单里"当前应用：××"下面有"此应用设置…"（直达设置窗口里这个应用）和两个快捷开关"在此应用关闭联想""在此应用禁止记录"，和设置窗口改的是同一份。

**当前模式和默认模式**：菜单显示当前模式（中文／英文），单按 Shift 或点它切换的是当前模式，不改默认值。进入一个应用的输入框时：

- 开着"记住各应用上次的中英文模式"（通用，新装默认开）：用这个应用上次的模式，重启输入法后也记得；没记过的用它的默认模式（应用覆盖了就用应用的，否则用全局的）。只存和默认值不一样的那些应用（只有 bundle id）。
- 关着：每次切回一个应用都用它的默认模式；同一个应用里换输入框不变。
- 改了全局默认：跟随全局的应用记着的模式清掉，下次进去用新的默认；自己设了默认模式的应用不动。改了某个应用的默认模式，它记着的清掉。

### 出问题时

| 情形 | 表现 |
|---|---|
| 答复慢 | 光标处先显示原始输入串，候选窗不出现；按空格时没有候选就照原样上屏字母 |
| 卡死（询问 1 秒无任何答复） | 重启引擎；候选窗位置显示"引擎没有响应，正在重启"。重启期间空闲时按键放行；正在输入时已敲的输入串保留，输入键照样接上（引擎回来后重新询问），回车、空格上屏原始字母，Esc 放弃，数字忽略，其余按键先上屏原始字母再放行 |
| 崩溃 | 立即重启，期间按键同上 |
| 1 分钟内崩溃 3 次 | 停用：不再重启，按键放行；系统通知写明引擎名、标准错误最后几行，附"打开开发模式记录"入口；菜单里标出原因，用户手动重新启用（目前只在提示行和菜单里显示，系统通知未做；快捷键引擎的停用菜单里还不显示） |
| 被沙盒拦下 | 每种被拦的操作只在第一次通知，写明拦了什么、引擎说明里该补哪条声明（目前同上，只在提示行和菜单里） |
| 引擎的数据目录或临时目录被换成符号链接 | 不启动，写明原因（沙盒不跟随这些目录本身的链接，见 ADR 0006） |
| 协议版本不支持 | 不启动，菜单里写明原因 |

## 引擎

### 两种引擎

- **打字引擎**：回答询问。同一时间只有一个当前引擎，在壳的菜单里或用快捷键切换（ADR 0004）。随壳启动、常驻。
- **快捷键引擎**：声明自己的快捷键，和当前引擎共存，可以装好几个；第一次触发时启动，之后常驻（声明了 `arm` 的随壳启动）。快捷键和壳的键位或别的引擎冲突时，设置里标红且不启用。密码框里不触发。
  - **语音**是一个快捷键引擎（ADR 0016）：按住右侧修饰键说话，按下就录（`arm`），按住期间识别出的字只作为显示串，松开后一次上屏；光标处提示「正在听」「识别中…」「整理中…」。识别经转问交给主控的 `luoke-ime.transcribe` 任务，引擎不加载模型；终稿再交 `luoke-ime.tidy` 整理。语音引擎随输入法自带（`engines/voice`），设置「通用」里的「语音输入」默认关，打开了才启动、才向系统要麦克风；下面的「说完后整理」没选过时按内存定，内存 24 GB 及以下的 Mac 默认关；「按住哪个键说话」默认右 ⌥，可换成右 ⌘ 或右 ⌃（外接 Windows 键盘、对调过修饰键的，右 Alt 发出来的可能是右 ⌘），存在设置的 `voice.key`，没选过不写，壳起引擎时用它盖过引擎说明里的 `hotkey.key`。
- **个人化组件**：一种特殊的引擎，同一时间一个，收所有引擎的上屏、回答转问，随壳启动、常驻（见"个人化与联想"）。

模型加载慢是引擎内部的事：加载完成前，引擎应先用快的办法答复（比如只查词库）。

### 文件布局

```
~/.luoke/ime/
  settings.json            壳的设置：候选窗、键位开关、当前引擎、应用例外、开发模式、记录（暂停、同意读写记忆）、主控的 socket（开发时）
  engines/<标识>/          引擎文件夹（引擎目录下的一个），对引擎只读
    engine.json            引擎说明
    ...                    引擎自己的程序和数据
  data/<标识>/             引擎数据目录，引擎唯一可写的地方
    options.json           用户改过的选项值
  records/<标识>/          开发模式下的输入记录，只有壳写
  usage.json               本机的使用计数：按天的次数，不记内容（见"评测"）
```

所有设置都是普通 JSON 文件，agent 可以直接改；壳监视这些文件，改动立即生效。

引擎文件夹对引擎只读，是为了让引擎改不了自己的引擎说明、给自己加权限；也让从 git 装的引擎保持干净。所以选项值存在引擎数据目录，而不是引擎文件夹。

### 生命周期

1. 壳启动时扫描引擎目录，读每个 `engine.json`；格式错误的引擎在菜单里显示为不可用，并写明原因。第三方引擎（不是随输入法发布的）确认过才启动，见[第三方引擎](#第三方引擎)。
2. 启动引擎：在沙盒里运行 `run`，工作目录为引擎文件夹；发 `hello`。
3. 引擎文件夹里任何文件改动、或选项值改动，壳重启这个引擎；下一个键用的就是新版本。
4. 退出：关闭标准输入，1 秒后强制结束。
5. 崩溃、卡死、停用的处理见上文"出问题时"。

### 沙盒与所需权限

每个引擎都通过 `sandbox-exec` 在 Seatbelt 沙盒里运行（ADR 0006）。规则是**默认全拒**，加上 Apple 的 `system.sb`（进程能起来所需的最小集），再按声明放开；实测见 research/seatbelt。

| 能力 | 默认 | 声明后 |
|---|---|---|
| 读文件 | 允许；但输入记录、别的引擎的数据、壳的设置、`~/.luoke` 下螺壳其他工具的数据（比如记忆 `mem.db`）、钥匙和凭据（`~/.ssh`、钥匙串等）、浏览器和邮件的数据、shell 历史不可读 | 个人化组件声明 `memory` 后可读写记忆文件 |
| 写文件 | 只允许引擎数据目录和临时目录 | `write` 里列出的位置；引擎文件夹、`~/.luoke/ime`、启动项、shell 配置、`~/.ssh` 永远不可写 |
| 联网 | 禁止（含名称解析） | `local`：只连本机 127.0.0.1 / ::1，可用 `local_ports` 限定端口；`any`：任意。unix socket 任何档位都不放行 |
| 麦克风、摄像头 | 禁止 | 允许，并在启用时向系统申请 |
| 屏幕录制 | 禁止（不放行抓屏所需的系统服务） | 允许，并在启用时向系统申请 |
| GPU（Metal） | 禁止 | 允许（引擎里跑本地模型用），含 Metal 着色器编译缓存 |
| 借别的程序间接外发（打开网址或应用、AppleEvents、剪贴板、创建后台任务） | 禁止 | — |

违规从系统日志读取（`log stream`），规则里每条禁止都带 `LUOKE[<引擎>] <类别>` 标签，引擎派生的子进程被拦也认领得到（命令行版起的引擎，标签前加 `cli.<进程号>.`，正在运行的输入法不会认成自己的）；菜单里每项只写做了什么、对着哪里，点一下复制完整说明；"写""联网"这类要用户或作者处理的才提示，名称解析、字节码缓存这类只记录。

系统权限只能整体授给壳，不能单独授给某个引擎（ADR 0005）。所以真正区分引擎能力的是沙盒，系统授权只是前提。壳的 Info.plist 预先写好所有可能申请的权限的用途说明。

### 第三方引擎

装在引擎目录（`~/.luoke/ime/engines`）里、不是随输入法发布的引擎，规矩更严（luokelabs/luoke-ime#6，ADR 0012）：

- **不能联网**，也不能用 GPU、写数据目录以外的地方：声明了 `network`（`none` 以外）、`gpu`、`write` 的不启用，菜单里写明原因。要用模型就经壳转问主控（顶层 ARCHITECTURE §2：第三方引擎只经主控的任务）。
- **用户确认了才启用**：在菜单里第一次选它，壳弹系统的确认框（默认按钮是"不启用"），写明它装在哪、启用后能做什么、不能做什么。确认记在设置里（`approved_engines`：引擎标识 → 引擎说明里和权限有关的内容的指纹），这些内容变了要重新确认；只改代码、选项、名字不用，因为沙盒只放行声明过的。
- **不自动选中**：没设当前引擎时用自带的。和自带的同名的第三方引擎，确认前照旧用自带的那份，确认后才代替它；记忆同意按"标识@指纹"记，不继承自带那份的同意。
- 新放进引擎目录时，候选窗里提示一次"在输入法菜单里确认后才能用"。

另外（不只第三方）：没允许"保存到本机记忆"时，上屏、删改、忘掉不转给任何个人化组件；联想、打分照常问它。

### 引擎选项

引擎在引擎说明里用 A2UI v0.9.1 格式描述选项界面，组件只能来自壳的组件目录（ADR 0008）。壳在设置窗口里为每个引擎画一页，用系统样式；值存到引擎数据目录的 `options.json`，启动时经 `hello` 交给引擎，值变了就重启引擎。第一版只做静态界面。

## 个人化与联想（上屏写进记忆、打分、联想已做；带个人化的打分、常用说法还没做）

分工见螺壳顶层设计（`../ARCHITECTURE.md`）和顶层 ADR 0014：模型推理归主控（luoke-core），理解归记忆（luoke-mem），怎么用在输入法里。本机组件之间不为隐私设限（顶层 ADR 0013）：个人化组件能读记忆里的全部记录和理解，保留的是安全上的规矩（安全输入不记、第三方代码进沙盒）。输入法这一侧加一个组件、几种消息和一个界面（ADR 0010）。

壳的那一半已做：个人化组件这种引擎、上屏转给它、转问、沙盒放行记忆、"暂停记录"和"不记录"、联想的界面。自带的个人化组件（`engines/personal`）把上屏写进记忆、给小鹤和全拼打分、给联想。

### 三方各管什么

| | 管什么 |
|---|---|
| 壳 | 把所有引擎（打字和语音）的上屏转给个人化组件；在引擎、个人化组件、主控之间转问，按声明放行、不看内容；联想的界面 |
| 个人化组件 | 一种特殊的引擎，在沙盒里，同一时间一个：把上屏写进记忆；读记忆里的记录和关于用户的理解（由 luoke-mem 归纳，顶层 ADR 0015；只用"比较确定"以上的）；回答带个人化的打分、联想、热词；要用模型时经壳调主控 |
| 打字引擎、快捷键引擎 | 自己的转换（按键或声音变成文字）；要个人化时经壳问个人化组件 |

### 数据怎么走

- **上屏**：壳把每次上屏（带应用、来自哪个引擎）转给个人化组件，它写成记忆里的一条记录；上屏后马上删改、在候选里改选、忘掉一个候选，记成另一类记录。
- **打分**：小鹤引擎重排时问个人化组件"这几个候选在这段前文后面各有多可能"；个人化组件把关于用户的理解和用户最近写过的话加进前文、给含常用说法的候选加分，再向主控要打分。
- **联想**：上屏后壳在后台问个人化组件；它从用户常接在这段话后面的说法里找候选，交主控打分，和模型接着写的一起排序、不通顺的去掉，答复给壳。
- **热词**：语音引擎开始识别前，问个人化组件要用户常用的专名和说法。

### 协议

字段见[引擎协议](引擎协议.md#个人化组件)的"个人化组件"和"转问"。要点：

- **引擎说明**：`kind: "personal"`；权限 `memory`（只有个人化组件能声明，沙盒只为它放行 `~/.luoke/mem.db` 和 SQLite 的附属文件）；别的引擎用 `asks` 声明要转问谁。
- **转问**：引擎发 `ask`（`to` 是 `personal` 或 `hub`），壳换号转给对方，再把 `reply` 换回原号转回。壳只检查声明和格式，不看内容；等多久由发问的引擎定。转问在后台线程上走，不经过壳的主线程。
- **个人化组件收到的**：打字引擎的上屏、标点、快捷键引擎的上屏（`committed`，带 `kind`、`source`、应用）、上屏后的退格（`deleted`）、忘掉（`forget`）、转来的 `ask`（带 `from`）。
- **个人化组件提供的方法**：`score`（前文 + 候选 → 各自的对数概率）、`predict`（前文 → 几个接着写的候选）、`hotwords`（→ 记忆里的常用说法，给语音；只有自带的引擎能问），还没做的答 `not_implemented`。
- **两条安全规则**（它看得到用户在所有引擎里的输入，壳在引擎说明上把关）：个人化组件不能联网；声明了要转问它的引擎不能联网出去（只能 `none`，或 `local` 加上限定的端口）。

### 联想的界面

- 用空格、数字选定候选上屏，或者上屏了标点、快捷键引擎（语音）上屏之后，壳在后台问个人化组件 `predict`（回车上屏字母、切走、按别的键收尾时不问；安全输入时不问；第三方的个人化组件在"禁止记录"的应用里、暂停时、记忆记录关着时也不问，见下面"什么交给个人化组件"）。上屏后停 0.25 秒没有按键才问：快打时接连上屏的短词不一个个去问，免得和下一个键的重排抢模型、卡一下；问出去 1 秒内没答复就不要了。
- 有联想时，候选窗里直接淡淡地列出联想：只占一行、最多 3 个、字小一点，不带编号（数字这时选不了），第一个前面一个 ⇥；打字照常不受影响，4 秒后自己收起（原先只提示"⇥ 联想"，先做的版本上面多一行提示、窗口比打字时大，挡界面）。
- 列着的时候按 Tab，激活联想候选：高亮的那个显示在光标处（拼音显示在候选窗里的模式也一样；像正在输入一样；Chromium、Electron 里输入法吞掉一个键却没有显示串时，它会把这个键再交给网页，Tab 就把焦点移走了。打开联想的那一下 Tab 光标处还没有显示串，有的应用照样自己处理这个 Tab：Grok 这类 Electron 应用会插一个制表符。这时选词会把联想上屏、再把那个制表符换掉；收起联想不去掉，按一下退格就行）；数字选，空格选高亮的，方向键和 Tab 移动，Esc、回车、退格收起；选中的直接上屏，也算一次上屏（转给个人化组件，`kind` 是 `predict`），然后接着问下一个。
- 没有联想时 Tab 照常交给应用；列着还没激活时按别的键，联想收起、这个键照常处理。
- 通用里可以整个关掉联想，应用设置里能单独开或关（菜单里当前应用下面有"在此应用关闭联想"），装了个人化组件时才有。
- 个人化组件的联想先找用户自己写过的（最近的上屏里，前文末尾的几个字后面常接什么），再请模型接着写几种说法、太没把握的不要。写过的不是写过就给：要模型判断接在这会儿的前文后面通顺才留下，和模型的一起按把握排；单字的不给，没有模型时不给（宁可少出，出了全不对就是打扰）。命中率见 `engines/personal/eval_predict.py`（博客语料、只看模型）和 `eval_personal.py`（用户自己的上屏按时间切开）。

### 什么交给个人化组件

照一张表（`Sources/LuokeShell/PersonalPolicy.swift`，顶层 ADR 0013；原来散在好几处，是一处处补出来的）：

| | 上屏、删改、忘掉（写记忆） | 打字引擎学改选 | 引擎的打分、壳的联想 |
|---|---|---|---|
| 安全输入（或这段组字里碰到过） | 不给 | 不学 | 不给 |
| "禁止记录"的应用、暂停所有记录 | 不给 | 不学 | 自带的照给（它不存这些请求）；第三方的不给 |
| 记忆记录关着 | 不给 | 照学 | 自带的照给；第三方的不给 |
| 其余 | 给 | 学 | 给 |

- **记忆记录默认开**：通用里的"记录输入内容到记忆"（菜单里关着时是"开启记忆记录"，直达这里），自带的个人化组件默认开；第一次切到螺壳时在候选窗里提示一句"螺壳会从你打的字里学，记在本机的螺壳记忆里；不想要的话在输入法设置的「通用」里关"，留到第一段字打完（上屏或取消）。带着提示打完一段才记成提示过，以后不再给；没打字就切走的，下次进输入框再给。设置里存的是用户关掉了谁（`memory_off`）；旧版里问过却没开的，照旧关着。关着时沙盒不放行记忆文件。第三方的个人化组件要用户另外打开才给（`memory_consent`，键带指纹）。
- 安全输入（密码框等）时什么都不记，这是安全上的。
- "禁止记录"的应用、"暂停所有记录"是用户自己的开关，照办；暂停不删已有的。
- 记忆打不开时（主控没装、luoke_mem 导入不了或太旧），菜单里标出来，不写记忆，输入照常。组件用主控带的那份 luoke_mem（luoke-mem 的约定），不自带。
- **凭证只遮那一串**（顶层 ADR 0013）：密码、验证码、密钥和令牌、完整卡号和证件号，用 luoke_mem 的 `mask_secrets` 遮成"〔密码〕"这样，其余照记；改选、删改、前文里的也遮。老版 luoke_mem 遮不了时，含凭证的那段不记。健康、法律、宗教政治照 `sensitive_kinds` 标上类别写进去，标了不藏（推出来的要用户点头才生效，由 luoke-mem 管）。
- **上屏记录带前文**：这一段开始时光标前的字（最多 200 字）放在 `data.context`、标成第三方写的（可能是别人的话），记忆只拿它理解上下文、不当用户说的。
- 联想用用户写过的全部上屏。
- 写进记忆的东西能看依据、能改、能忘掉，在螺壳记忆里（输入法菜单的"管理记忆"，`open luoke://memory`；没有认领它的应用时退回旧的螺壳记忆.app，都没有时显示成灰的"还没装螺壳主控"）。关于用户的理解由 luoke-mem 归纳（顶层 ADR 0015），输入法只读来用，忘掉候选时对来自常用说法的那条调 `reject`。
- 打字引擎自己记的改选过的词在它的数据目录里（小鹤是 `memory.json`），不进记忆；在候选上按 Shift+⌫ 忘掉，忘掉的存原文，记忆页里列出"忘掉过的词"、能撤销（早先只存了哈希的留着当拦截名单）。菜单里"清掉「引擎名」学到的词"弹系统的确认框（默认按钮是取消），确认后壳发 `forget_all`，引擎把改选过的词整个清掉。
- 上屏原文默认一直保留；用户可以在输入法里设保留期，过期的原文删掉，被理解引用的留下作依据（个人化组件的选项"上屏原文保留多久"）。

### 分期

1. 个人化组件，加上"上屏写进记忆"：先开始攒素材（已做，在本机写真实的记忆；话题和写法和 luoke-mem 商定，见顶层的注册页 `../projects/luoke-ime.md`）。
2. 打分搬进个人化组件，小鹤、全拼改成转问它（已做：模型只加载一份，在个人化组件里）；加上个人化（前文里加理解和最近写过的话，常用说法加分，还没做）。
3. 联想（已做：用户自己写过的 + 模型接着写）。
   慢的机器：主控按实测给重排标了 slow（比如 M1），小鹤、全拼每一步少给模型一半候选，一次重排最多 2 步（第 2 步整句一起定，停下来后再不限步数选一遍）；按实测分，不按内存档位。模型算着时来了新键，先答它快的那份（所有机器）。
4. 主控上线：个人化组件的模型请求改走主控（进行中：壳能把 `to: "hub"` 的转问转给主控，个人化组件的选项 `scorer` 是 `hub`（默认）或 `auto` 就经主控打分）。发布版只经主控、没有本机退路：本机打分要借用户自己装的 oMLX 里的 Python，干净的 Mac 上没有；主控不可用时照常打字，只是没有重排和联想。
5. 语音引擎接热词和打分。

### 评测

博客语料只用来评测不带个人化的重排（它来自用户自己的网站，一旦导入记忆，就不能再用来评个人化）。个人化和联想的效果，用用户自己的上屏按时间切出最近的一段留作测试，这一段不参与学习。

语音转写的评测在 `evals/transcribe`：评测集自己写的句子（日常、专名、中英混说、标点、长句、数字），跑的时候用 macOS 的 `say` 现合成（默认 Tingting，出版机只有这个声音；`--voices tingting,eddy` 加一个），照语音引擎的用法经主控送，算字准确率（数字那一类不算）和松开到终稿的用时；硬性条目是按住不说话不出字。主控的发布流水线用它评 `luoke-ime.transcribe`。语音的整理在 `evals/tidy`：转写原文和应该整理成的样子（口头禅、改口、数字、英文），总分是整理后的字准确率，硬性条目是本来通顺的和像在对模型下指令的一个字都不改。

离线评测看的是「会不会对」，看不到用户真用的时候选没选。壳另记一份**使用计数**（`Usage`，`~/.luoke/ime/usage.json`）：只有按天合计的次数，不记打了什么、在哪个应用，不上传，留 90 天。记的是打字引擎的上屏次数、选的候选里首选和别的各几段、上屏后紧接着按退格的次数（每次上屏最多一次），联想亮出、打开、选中的次数和选中的字数。密码框里（这一段里碰到过也算）、暂停所有记录、禁止记录的应用里不记；和记忆记录开没开无关（只有次数，不进记忆）。设置窗口「高级」里显示最近 7 天、能清零；评测时读这个文件，和离线评测对照（比如联想亮出了却很少被打开，就是打扰多）。

## 壳的设置

菜单只放常用操作，全局默认值和按应用覆盖在设置窗口里（luokelabs/luoke-ime#1，ADR 0011）。菜单和设置窗口改的是同一份设置（`settings.json` 第 2 版），外面改了文件两边都跟着变。

菜单（从上到下）：

- **输入方案**：各个打字引擎，勾的是当前的；停用、沙盒拦截的提示也在这里。
- **当前模式：中文／英文（⇧ 切换）**：点一下切换当前模式。
- **当前应用：××**：此应用设置…（后面写"跟随全局"或"已自定义"）、在此应用关闭联想、在此应用禁止记录。
- **记忆记录：未开启／已暂停／当前应用禁止／记录中／不可用**：按实际状态写，组件不可用时不写"记录中"。下面是"开启记忆记录"（打开设置的「通用」）或"暂停所有记录／恢复记录"、"管理记忆"（打开螺壳记忆）、"清掉「引擎名」学到的词"。
- **设置**、**记忆**、**高级 ▸**（菜单项不带「…」）（开发模式、打开引擎文件夹、打开设置文件）。
- macOS 自带的菜单项（显示输入法名称、键盘设置等）照旧，不重复做。

设置窗口四页（窗口里不放文本框：输入法自己的窗口里打字，按键会交给输入法自己）：

- **通用**（原全局设置）：输入方案；中英文（进入应用时默认中文或英文、记住各应用上次的模式、单按 Shift 切换）；排版（中英文之间加空格）；候选窗口（字号、横排或竖排、每页个数、翻页键 `-` `=` 或 `,` `.`）；拼音显示（输入框里或候选窗口里）；联想（开或关：根据已输入的文字推荐后续内容，按 Tab 选，也可以继续打字）；记忆记录（装了个人化组件时：现在的状态、"记录输入内容到记忆"总开关（同意个人化组件读写记忆，默认关；关掉不删已有的、也不清各应用的禁止记录）、暂停所有记录）。
- **应用设置**：设过的应用和从菜单进来的那个，每个应用四项，见[应用设置](#应用设置)，显示跟随的全局值（记忆记录写"跟随全局（已开启／已关闭／已暂停）"）。
- **记忆**（原隐私与记忆，装了个人化组件时）：记了什么、存在哪、哪些时候不记；查看和管理记忆（打开螺壳记忆）；清掉引擎学到的词。不放总开关（总开关在通用，luokelabs/luoke-ime#1 的后续）。
- **高级**（原诊断与开发）：使用统计（最近 7 天的使用计数，能清零）；每个引擎的开发模式（写明记什么、存在哪、只留 7 天，和记忆记录是两回事）；打开记录文件夹、引擎文件夹、设置文件。

引擎自己的选项（A2UI）还没有原生的界面（首发以后做），现在改的是各引擎数据目录里的 options.json。

**螺壳主窗口里也有一份**（ADR 0018）：装了螺壳的，主窗口侧栏的「螺壳输入法」页能改通用页里的全部设置和各应用的设置，和这里的设置窗口并存、改同一份文件。螺壳本体按请求起包里的 `luoke-ime mcp`（luoke-agent 工具协议 §2a），它读一条请求、答一行就退出；只改 `SettingsService` 里写死的一张表，要用户在页上点过；「各应用」页展开的是哪个应用记在 `~/.luoke/ime/window-page.json`。学到和忘掉的词、使用统计、开发模式只在这里的设置窗口。输入法每秒看一次设置文件，外面改了马上生效，自己存盘前也先读一遍。

**模糊音**在通用页：总开关默认关；打开后下面才列出六组（z = zh、s = sh、c = ch、an = ang、en = eng、in = ing），默认全勾，可以按组取消，关着时不列（勾选照样留着）。一份设置三个打字引擎共用，存在设置文件的 `fuzzy`（`on`、`pairs`），壳经 `hello` 的选项 `fuzzy` 交给打字引擎（总开关关着时是空数组），改了就重启打字引擎。an = ang 不包括 ian/iang、uan/uang。苹果转换引擎用 `MecabraSetFuzzyPinyinPairs` 加分析选项 16（私有接口，系统没有这个函数时这一路不开）；RIME 在方案补丁里给 `speller/algebra` 最前面加 `derive` 规则，换设置时只重编拼写表，不到一秒。

**设置文件第 2 版**：`version: 2`；`defaults`（english、remember_mode、inline、predict）、`apps`（按应用的覆盖：english、inline、predict、no_record，没写的跟随全局）、`app_modes`（记住的各应用上次的模式），其余（候选窗、键位、记录、开发模式、主控的 socket）和原来一样。第 1 版（没有 `version`）的 `app_exceptions` 读进来时一次换成第 2 版：no_inline → inline 关、english → 默认英文、no_record → 禁止记录、no_predict → 联想关，全局的 predict 照旧；先把原文件另存为 `settings.v1.json`（已经有了不覆盖），另存不成就不写回、原文件不动，菜单里标出来。迁移不会多开任何记录。

## 开发工具

### 命令行版 `luoke-ime`

| 命令 | 作用 |
|---|---|
| `luoke-ime try <引擎文件夹>` | 在终端里打字：显示串和候选以文字显示，键位和输入法完全一致；引擎文件一改就自动重启 |
| `luoke-ime try <引擎文件夹> --keys '<按键脚本>'` | 不需要终端：按脚本打字，逐键打印光标处、候选和输入框，给 agent 用 |
| `luoke-ime mcp` | 读一条 JSON-RPC 请求、答一行：螺壳主窗口里的设置页（ADR 0018），由螺壳本体起 |
| `luoke-ime try … --personal <文件夹>` | 同时装上个人化组件，列出转给它的消息；记忆用临时的一份；`--hub <socket>` 写明连哪个主控 |

试用、检查、评测都不碰日常在用的实例：`try` 的数据目录默认是临时目录里固定的一份（`--data` 可改），`check` 每次用一次性的，`bench.py` 经主控时必须写明 `--hub`，找不到就报错、不退回装好的那个。
| `luoke-ime check <引擎文件夹>` | 自动检查，输出 agent 可直接读的报告 |
| `luoke-ime replay <输入记录> [--engine <文件夹>] [--fast]` | 把一段输入记录重放给引擎，逐键打印，并对比每次询问的首选和当时是否一样 |
| `luoke-ime install <git 地址>` | 克隆到引擎目录，先列出所需权限，确认后启用（未实现） |
| `luoke-ime list` | 列出引擎和它们的引擎说明是否合法（运行状态、停用原因要等 macOS 外壳做好后由它提供） |

`check` 检查的内容：

- 引擎说明是否合法；
- 能否在 5 秒内启动；
- 对一组随机输入串（由输入键生成）的答复：格式、`id`、`consume` 范围、`more` 语义是否正确，首个答复的延迟分布；
- 标准输出有没有混入非 JSON 的行；
- 收到不认识的消息类型时会不会崩；
- 有没有被沙盒拦下，被拦的是什么、该补哪条声明；
- 关闭标准输入后能否在 1 秒内退出；
- 声明了 `feedback` 的，发一组反馈后是否还活着；
- 个人化组件：发一组上屏、退格、忘掉后，转问（含连发、不认识的方法）是否都按号答复。

### 开发模式和输入记录

开发模式按引擎单独开关，默认关闭。打开后，壳把它和这个引擎之间的每条消息，连同按键和时间，写成输入记录（JSONL）。记录里有按键，所以只存在本机的 `records/` 目录里，壳不会发到任何地方。安全输入、"不记录"的应用、暂停记录时什么都不记（连引擎的收发），和上屏转给个人化组件的规则一样；只留最近 7 天的（每开一份新的时删掉更早的）。输入记录可以在命令行版里回放，用来复现问题和做回归测试。

## macOS 外壳实现要点

- 基于 InputMethodKit。每个输入框一个输入控制器，各自持有一份状态机实例；接收 `keyDown` 和 `flagsChanged`（Shift 单按、右侧修饰键快捷键）。
- 显示串用 marked text；"显示串不内嵌"的应用里不设置 marked text。
- 候选窗用自己的 NSPanel 加毛玻璃，不用 IMKCandidates。光标位置取自客户端的字符矩形。
- 前文通过客户端读取光标前的文字；先检查是否处于安全输入状态。
- `deactivateServer` 和 `commitComposition` 时收尾上屏；`cancelComposition` 时丢弃。
- 引擎宿主运行在独立线程，读写管道不阻塞主线程。
- 系统里只注册一项输入法，标识 `ai.luoke.inputmethod.Luoke`，显示名"螺壳"（英文系统里"Luoke 螺壳"），登记语言为简体中文。
- 首次安装必须由用户在系统设置里手动添加一次：macOS 26 起，第三方输入法的启用记录在 `com.apple.inputsources` 的 `AppleEnabledThirdPartyInputSources`，只有用户在系统设置里确认（"开发者能读取你用这个输入源输入的一切"）才会写入；程序调用 `TISEnableInputSource` 返回成功却不生效，选中会报 -50。系统设置只在打开时读一次输入源列表，装完要重新打开它。重装（同一个标识）不需要再添加。
- 修饰键事件先看区分左右的设备位，没有时退回看设备无关位：屏幕共享、远程桌面、辅助工具合成的按键常常不带设备位。

- 换版：旧进程找资源、起引擎都按包的路径，换包后不能留着跑旧代码。主控换好包以后结束跑在换下来那份里的进程（SIGTERM，3 秒后 SIGKILL），再 `open -g` 装好的路径。输入法自己也兜一层：每 5 秒看一次磁盘上包里的 build 号，和启动时的不一样了，就等所有输入框都空闲（没在组字、没挂着逗号、联想候选没打开）、最近 3 秒没按键时收尾退出，并在退出后 `open -g` 拉起新版（`UpgradeWatch`）。

## 测试

1. **状态机单元测试**：用假引擎和可注入的时钟，覆盖全部键位、先快后好的五条规则、收尾上屏、反馈事件。这一层最全。
2. **协议一致性**：`luoke-ime check` 本身就是引擎的测试；对壳自带的三个引擎在持续集成里跑。
3. **跨应用测试矩阵**：在测试机上自动化，每次改动 macOS 外壳都重跑。
   - 第一档（作者日常使用前必过）：微信、Safari、Chrome、备忘录、Telegram、VS Code 或 Cursor、终端。
   - 第二档（公开发布前必过）：邮件、文本编辑、飞书或 Slack、Claude/ChatGPT 桌面版、Google Docs/Notion 等网页编辑器、聚焦搜索。
   - 每个应用的检查项：显示串内嵌、候选窗位置、部分选词与退格撤销、上屏、前文能否读到、上屏后的退格能否观测、快捷键引擎推送上屏、切走时自动上屏、密码框里不读前文。
   - 不过的项，要么修好，要么写进应用例外的自带名单。
   - 自动化沿用之前在测试机上的经验：先切好输入法再激活目标应用；用前台窗口归属核对焦点；每次用新的草稿文件等。

## 分发与许可

- 壳以 Apache-2.0 开源，不加商业限制；另写名称和图标使用说明（ADR 0009）。鼠须管、威注音只参考行为，不抄代码。
- Developer ID 签名、公证，经 GitHub Releases 分发，以后加 Homebrew。
- 壳本身不收集任何使用数据，也不联网检查更新。
- 引擎各自选许可证。小鹤引擎若打包雾凇词库（GPL-3.0-only），引擎须遵守 GPL；引擎是独立进程，不影响壳。
