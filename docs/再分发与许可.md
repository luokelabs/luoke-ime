# 再分发与许可

v1 的主控和配件放公开的 GitHub Releases，输入法也跟着公开分发。这一页查清输入法带的第三方东西能不能再分发、要尽什么义务、有什么风险。模型（Qwen3.5-0.8B）在主控里，python-build-standalone 由主控的打包脚本统一处理（luoke-core `docs/research/redistribution-licenses.md`）。

不是法律意见；有拿不准的，发布前请懂行的人再看一眼。

## 一览

| 东西 | 用在哪 | 许可 | 现在怎么来 | 公开发布时 |
|---|---|---|---|---|
| 壳（LuokeIME.app、命令行版） | 输入法本身 | Apache-2.0（我们的，ADR 0009） | 本仓库 | 只用公开的系统接口；照常签名公证 |
| 小鹤、全拼、个人化组件、最小示例 | 自带的输入法引擎 | Apache-2.0（我们的） | 本仓库 | 同上 |
| librime 1.17 和它的四个插件（lua、octagram、predict、proto） | 小鹤、全拼的 `rime_helper` | 都是 BSD-3-Clause | Homebrew 装的动态库（`/opt/homebrew/opt/librime`），插件在 `lib/rime-plugins`，运行时都会加载 | 要随引擎带上（动态库改装载路径，或静态链接），附许可 |
| librime 的依赖 | 同上 | capnp（MIT）、gflags（BSD-3）、glog（BSD-3）、leveldb（BSD-3）、snappy（BSD-3）、lua（MIT）、marisa（BSD-2 / LGPL-2.1 二选一，取 BSD）、opencc（Apache-2.0）、yaml-cpp（MIT） | Homebrew | 跟 librime 一起带，附各自的许可 |
| 雾凇拼音（rime-ice） | RIME 的词库和方案（约 48 MB 的 YAML 和少量 lua） | GPL-3.0-only | `build.sh` 从 GitHub 克隆进 `vendor/`，不进仓库 | 随引擎包原样带上，附 GPL 全文和来源 |
| 苹果的转换引擎（libmecabra） | 小鹤、全拼出候选的主力 | 系统私有库，不随我们发布 | 每台 Mac 自带 | 不涉及再分发；继续用、公开写明风险 |
| oMLX 自带的 Python 和 mlx_lm | 个人化组件退回本机打分时 | （不随我们发布） | 用户自己装的 oMLX | 不带：没装 oMLX 时，主控不可用就不重排 |

## librime 和它的依赖

都是宽松许可（BSD、MIT、Apache-2.0；librime 和插件的许可查自 Homebrew 的 SBOM 和 GitHub），可以再分发，义务是**附上版权声明和许可全文**（Apache-2.0 另要附 NOTICE，如果有）。要做的是打包：现在 `rime_helper` 链的是 Homebrew 的路径，别人的机器上没有（实测运行中的 `rime_helper` 加载了 librime、四个插件和上面九个依赖，共 15 个动态库）。发布时把它们放进引擎文件夹、用 `install_name_tool` 改成 `@loader_path`，签名进同一个包；或者静态链接。插件里只有 librime-lua 是雾凇用得上的（它的 lua 脚本靠它跑），其余三个用不上，可以不带。许可全文汇成一份 `THIRD_PARTY_NOTICES`。

## 雾凇词库（GPL-3.0-only）

- **是什么**：词库和方案，绝大部分是 YAML 文本（也就是它的"源码"本身），另有几个 lua 脚本（RIME 的 lua 插件执行）。现在 `vendor/rime-ice` 里**没有它的 LICENSE 文件**（克隆后同步时没带上），发布前要补。
- **随包带的义务**：附 GPL-3.0 全文、注明来源和版本（上游仓库地址和提交号），并提供对应源码。我们带的就是 YAML 原文，源码随包附带即满足；编译后的词典（`.bin`）在用户机器上第一次运行时才生成，不随包发。
- **会不会把我们的代码"传染"成 GPL**：引擎（小鹤、全拼）是独立的程序，把雾凇当数据读；lua 脚本由 librime-lua 里的解释器执行，按 GPL FAQ，被解释执行的程序对解释器来说只是数据，不会让解释器（以及链着它的 `rime_helper`）受 GPL 约束；`rime_helper` 和引擎之间又隔着管道。所以引擎和壳仍是 Apache-2.0；雾凇作为单独的一份、原样带着、写明它的许可（"聚合"）。ADR 0009 里"引擎须遵守 GPL"的说法偏保守，定下来以后在那里追加修订。
- **三种做法**（定了第 1 种）：
  1. **随引擎包带**（推荐）：原样带上、附许可和来源。离线就能用，和"离线方案"一致；义务很轻（YAML 本身就是源码）。
  2. **第一次运行时让用户自己下载**：我们不再分发它，但引擎在沙盒里不能联网，要另做一个下载步骤（壳或主控的安装流程），离线装不上；上游改了格式还可能装坏。
  3. **公开版不用 RIME**：只用苹果的候选加模型重排，打包最省事（不带 librime 和 15 个动态库，也没有 GPL 的东西）。代价见下面的实测，另外苹果的转换引擎哪天失效时就没有退路了。

### RIME 值多少（实测）

M5 Max，博客语料 600 条，小鹤引擎经本机模型重排（`bench.py --typing 0`，`--engine-option rime=false` 关掉 RIME）：

| | 立刻给出的首选 | 模型重排后的首选 | 最后一个键到选好 p50 / p90 |
|---|---|---|---|
| 苹果 + RIME（现在） | 78.8% | 89.8% | 42 / 70 ms |
| 只有苹果 | 78.8% | 87.7% | 37 / 62 ms |

RIME 不改立刻给出的首选（苹果排在前面），它的用处是给模型多一些候选去挑：重排后多对 2.1 个百分点（600 条里约 13 条）。另外：拼不成小鹤音节的英文单词多一个来源；苹果的转换引擎失效时，有了它才有可能接着出候选（现在还没做，引擎是整个停用）。

## 苹果的转换引擎（libmecabra，私有库）

- **不涉及再分发**：它是 macOS 自带的系统库，我们不带它，只在运行时打开、调用它导出的函数。
- **苹果的条款**：Apple Developer Program License Agreement 第 3.3.1(A) 条写"不得使用或调用私有 API"，但第 3.3 节开头说明它管的是提交到 App Store、Custom App Distribution、TestFlight 或 Ad Hoc 分发的应用；我们用 Developer ID 签名、公证后自己分发，不在这几种里。第 5.3 节说公证是对恶意软件和安全问题的自动检查（少数情况人工），没提审 API 用法；实际上公证查的是签名、加固运行时和恶意代码，私有接口的动态调用（`dlopen`、`dlsym`）不在检查之列（连同用私有库的小鹤、全拼一起公证过，Accepted）。但第 5.4 节保留了苹果"随时、自行决定"吊销证书和公证票据的权利（包括违反协议任何条款时）。
- **风险**：
  - 系统升级可能改掉或去掉这些函数：引擎启动时自检，失效就退出、壳停用它并说明原因（已做）；macOS 26、27 上验证过。
  - 苹果认定违规而吊销：可能性低。吊销分两种：只吊销某一份的公证票据，就只影响那一份；吊销开发者证书，同一个证书签的所有 app（主控、邮件助手、记忆）都受影响，这个分不开（除非另开开发者账号）。所以用私有库的小鹤、全拼引擎宜单独成包、单独公证，不和主控打在一起；这件和 luoke-core 的打包一起定。
  - 不能上 App Store：本来就不上（设计.md「非目标」）。
- **备选**：不用它就只剩 RIME 出候选（雾凇），首选准确率会明显低于苹果（博客语料上苹果单独 78.8%，RIME 单独没测过，第一步评估时 RIME 的首选不如苹果，见设计.md 分期）；所以推荐继续用，公开说明"调用了 macOS 的非公开接口、系统升级后可能失效"。现在失效时小鹤、全拼整个停用（壳里写明原因）；带着 RIME 的话，以后可以改成退回只用 RIME 出候选，不至于完全不能打字。

## 定下的

1. 雾凇词库**随引擎包带**：原样带上 YAML 和 lua，附 GPL-3.0 全文、上游地址和提交号。
2. 苹果的转换引擎**继续用**，公开写明"调用了 macOS 的非公开接口、系统升级后可能失效"。

已追加到 ADR 0009 的修订。
