# 个人化放进输入法里一个单独的组件，壳只转话

用户的用词和习惯对拼音、双拼、语音输入都是最重要的权重，联想也离不开它。输入法这一侧的个人化交给一个单独的**个人化组件**：它是一种特殊的引擎，在沙盒里运行；接收所有输入法引擎（打字和语音）的上屏，写进螺壳的记忆（luoke-mem）；空闲时归纳常用的说法；回答"带个人化的打分""联想""热词"三类请求；要用模型时经壳调主控（luoke-core）。打字引擎和语音引擎需要个人化时，经壳问它。壳在三方之间转话、按声明放行，不看内容；联想的界面由壳画。

这是螺壳顶层 ADR 0001（模型在主控、数据在记忆、怎么用在工具里）在输入法里的落实。理由：壳不懂语言规则是输入法的设计原则（目标与非目标），个人化的逻辑处处是语言规则；而把它分散到每个输入法引擎里，每个引擎都要读用户的原始历史、各学各的，语音引擎和打字引擎互不相通。一个组件、一份数据、所有引擎共用，用户的历史也只有它能看到。

## Considered Options

- **放进壳**：否决，壳要懂语言、跑模型，最敏感的数据落在不在沙盒里的进程里，也换不掉。
- **每个输入法引擎自己做，共用一个代码库**：否决，见上；而且语音引擎上屏的字，打字引擎根本收不到（现在的上屏反馈只发给出字的那个引擎）。
- **个人化组件自己加载模型、自己存数据（第一版提议的"个人模型"）**：否决，和主控、记忆重复，见顶层 ADR 0001。

## Consequences

- 引擎协议要加东西：一种新的引擎类型（个人化组件，同一时间一个）；"读写记忆"权限（只给它，安装时列给用户）；输入法引擎经壳向个人化组件或主控提请求（转问）的消息；壳把所有引擎的上屏转给个人化组件。
- 小鹤、全拼引擎现在自带的打分进程，先搬进个人化组件，主控上线后再换成主控的任务；引擎这边只改成转问，接口不再变。
- 主控不可用、个人化组件没装或出了问题时，输入照常，只是没有重排、个人化和联想。
- 上屏写进记忆是最敏感的一步：安全输入时不记，按应用可关、可暂停，写入前过滤敏感类别。
- 联想用 Tab 打开、数字选；Tab 在很多应用里有用，所以只在刚上屏、有联想时才接管，并在光标旁给出提示。

## 修订（2026-10-16）

"空闲时归纳常用的说法"不再归个人化组件：关于用户的理解（常用说法、关注的话题等）由螺壳记忆从所有工具的记录里归纳（顶层 ADR 0005，2026-10-14 定）。个人化组件只写记录（上屏、改选、删改、忘掉），联想时读输入法自己写过的上屏，以后读记忆归纳出的理解做热词；它不调 `conclude`、`propose`。出自顶层的越界自查（`docs/boundary-audit-2026-10.md`）。

## 修订（2026-10-19，顶层 ADR 全部归档重写以后）

上面引用的顶层 ADR 0001 已归档，分工以顶层 ADR 0014 为准。"写入前过滤敏感类别"作废：顶层 ADR 0013（本机组件之间不为隐私设限）以后，凭证只遮那一串、其余照记，健康这类只标类别不藏，上屏记录带前文（标成第三方），自带个人化组件的记忆记录默认开。见输入法 ADR 0013。
