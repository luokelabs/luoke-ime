# 设置放在螺壳主窗口里，输入法只给数据和动作

最早 2026-11-09 定的是在主窗口里多放一份，和输入法自己的设置窗口并存。后来改成只留主窗口那一页：测试的人觉得两套设置并存没有必要，团队决定合并，顶层 ADR 0002 也写明设置页的界面和措辞归 luoke-agent。

定下的：

- **只有一套**：设置页在主窗口侧栏的「螺壳输入法」应用里。输入法菜单的「设置」打开主窗口的那一页（主控的 `luoke://app/luoke-ime/settings`），「此应用设置」打开 `luoke://app/luoke-ime/apps?app=<bundle id>`。输入法自己的设置窗口只在打不开主窗口时兜底（螺壳还是不认这个地址的旧版），主窗口那页补齐以后去掉，在那之前只修错、不加新东西。
- **页由 luoke-agent 拼**：输入法只给原始数据，`data/settings`、`data/apps` 里只有代号、数字、日期、路径和应用名，不给句子；「各应用」页展开哪个应用，agent 用打开页面时带的 `app` 参数；叫什么、怎么分组、放什么按钮由 agent 定。字段、动作、答复和失败的代号写在 `fixtures/agent/README.md`，场景样例在 `fixtures/agent/`，测试里重录一遍和仓库里的比。
- **权限照旧**：麦克风仍由输入法自己要，配件清单里不写 `permissions`，不进螺壳的权限页。
- **怎么接**：照 luoke-agent 工具协议 §2a（`transport: "stdio"`）。螺壳本体按请求起包里的 `Contents/MacOS/luoke-ime mcp`，它读一条请求、答一行就退出，不常驻、不开 socket；输入法没在跑时设置页也能看、能改。配件清单写 `transport`、`data`（`settings`、`apps`）、`actions`（`ime_set`、`ime_do`）。旧的 A2UI 页（`page/settings`、`page/apps`，展开哪个应用记在 `~/.luoke/ime/window-page.json`）留到 agent 换过去。
- **只改一张写死的表**：`ime_set` 只认 `SettingsService` 里列的键，值的类型逐个核；确认第三方引擎（`approved_engines`，牵涉沙盒）、主控地址不在表里，输入方案只能选自带的和已经确认过的。开发模式单独走 `ime_do`（会在本机记录按键，页上要确认），也只能开能选的打字引擎。设置文件读不懂、还是第 1 版时不写。
- **都要用户点过**：`ime_set`、`ime_do` 没带 `ai.luoke/user-action` 的不做。清除、清零、开发模式开启的确认框在页上，由 agent 加。
- **要正在运行的输入法做的**：清除已学词语、恢复已忘记的词语（要经运行中的打字引擎）、清零使用计数（计数攒在它的内存里）。`luoke-ime mcp` 在 `~/.luoke/ime/requests/` 放一个请求文件，输入法每秒看一次，取走、做完、写回答复；3 秒内没人取走就取回请求，答输入法没在运行，免得之后才做。
- **两边同时改**：正在运行的输入法每秒看一次设置文件的修改时间，读到新的马上生效；自己存盘前也先读一遍外面改过的，不拿手里旧的那份盖掉（记住各应用的中英文模式时最常存盘）。

## Considered Options

- **两套并存**（11-09 到 11-19 的做法）：没装螺壳的人也能改设置。后来输入法改由螺壳安装和更新，没有不装螺壳的用法了；两套并存反而让人分不清该在哪里改。
- **输入法照旧画 A2UI 页**：主窗口里别的应用都是 agent 照数据拼，一页里不能一半输入法画、一半 agent 拼，措辞也管不到一处。
- **在输入法进程里开 socket**：输入法是系统按需拉起的，没在打字时可能不在；设置本来就在文件里，短命的命令行读写文件就够。要它做的几样用请求文件，和看设置文件是同一个每秒的检查。
- **已学词语给个数**：学到了多少只有引擎自己知道，各引擎存法不一样，壳不读引擎的私有文件。
