# 引擎是壳的子进程，每行一个 JSON，走标准输入输出

壳按引擎说明里的命令启动引擎，双方经标准输入输出逐行交换 JSON（和语言服务器协议同一路数）。这样任何语言都能写引擎，开发时在终端里直接运行引擎就能试；按键只经过壳和子进程之间的管道，不开任何端口；引擎崩溃时壳放行按键并重启它，不会拖垮输入法。

## 考虑过的做法

- **引擎常驻、壳去连它（本地 socket / XPC）**：便于多个程序共用一个引擎，但用户要自己管引擎的启停，且多出一个任何本机进程都可能连上来读按键的端口。需要共用大模型服务的引擎，应在自己内部去连那个服务，而不是让壳去连。
- **引擎作为插件加载进壳的进程（动态库 / JavaScriptCore）**：最快，但限制了写引擎的语言、跑不了模型，引擎一崩整个输入法跟着崩。
