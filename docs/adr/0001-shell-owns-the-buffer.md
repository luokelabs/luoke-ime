# 输入串归壳管，引擎只回答"这个串出哪些候选"

壳攒输入串，并统一处理退格、Esc、空格、数字选词、翻页、回车；引擎只按"输入串 + 前文 → 显示串 + 候选（各自用掉几个键）"作答，选中后壳删掉用掉的键再问一次。这样最小的引擎只有十几行、无状态、可回放测试，所有引擎手感一致——这是面向 vibe coding 的前提。

## 考虑过的做法

- **每个键都交给引擎，引擎自己管状态**（IBus、鼠须管的做法）：能力最强，但每个引擎都得重写退格、选词、翻页，写对的门槛高，手感参差不齐。

## 后果

- 引擎不能定义自己的按键行为（比如 Tab 跳词）；五笔四码自动上屏这类需求，靠候选上的"自动上屏"标记补。
- 语音这类不用输入串的引擎，走"引擎主动推送"的方向，不受此决定影响。
