# 打错纠正只纠读不通的按键，纠出的整句排第一、标 ✎

2026-11-05 定。双拼打错一个键，现在的引擎几乎救不回来：每句照真人的比例随机打错一处（漏打 47%、多打 28%、按错 19%、打反 7.5%），博客 600 句首选只对 4.3%。

做法（小鹤、自然码；`engines/xiaohe/Typo.swift`）：整串按键有一对读不通时，在第一个读不通的那对键和它前面 4 个键里改一处（按成相邻的键、多按一个相邻的键、漏一个、相邻两个打反），改完读得通的各取整串首选，交模型按前文挑最通顺的。挑出的随补发一起来，排第一、注释标 ✦（英文单词仍在它前面）；没有模型时不纠。博客 600 句 4.3% → 22.2%、WD 720 句 2.1% → 16.4%，打对的 1320 句三份答复逐条不变。

- **只纠读不通的**：双拼里打对的按键总读得通（末尾单独一个声母也算，那是还没打完），这样打对的字一个都不会被改，也不用每个键都让模型比一遍。代价是打错后仍读得通的抓不到：博客那 600 句里只有 258 句读不通，多数漏打、多打留下的是奇数个键、末尾正好是个声母，和「还在打」分不出来。
- **只改附近几个键**：错一定在第一个读不通的那对键上或它前面。只看前面 4 个键时平均试 26 种改法，不限位置要 75 种，纠回的只多 1%。
- **英文**：认识的英文单词仍排在最前，不受影响。不认识、又读不通的字母串，改一处能读通时会纠出一句汉字（28 个开发者常打的词里只有 `rustc` → 荣涛；原来它的首选也是半截的「如」）；要原样的字母照旧按回车，或者用大写字母开头打英文。
- **标 ✎**：原来和模型按前文改了首选用同一个 ✦（都是「慢的那一路改过」）。试用时分不清是按键被改了还是换了词，改成 ✎：✦ 是按前文换了词，✎ 是改了按的键。

## Considered Options

- **读得通的也纠**（原样加分，交模型和改过的比）：原型上纠回的多一倍（44%），但每个键都要试改、让模型比，慢；而且有把打对的改错的风险。等第一期真用的数字（使用计数里上屏后退格的比例）再看。
- **纠出的排第二**：最保守，但按空格得到的还是读不通时那些半截的汉字，等于没纠。
- **双拼也开简拼**（RIME 的 abbrev 规则，另一个方案、只在读不通时问）：分支 `xiaohe-abbrev` 上做过，半简拼 2.5% → 12.3%（WD），但读不通的串上候选慢到 190 ms（95% 分位），读不通又不认识的字母串空格从上屏字母变成上屏汉字，没合进来。
