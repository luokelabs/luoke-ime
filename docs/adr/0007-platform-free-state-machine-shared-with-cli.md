# 壳分两层：平台无关的状态机 + 很薄的 macOS 输入法外壳，命令行版共用状态机

输入串、已选部分、退格和选词规则、先快后好的三条规则，全部放在一个不依赖 macOS 输入法框架的状态机里；macOS 那层只负责把系统按键事件喂进去、把结果画出来和上屏。命令行版直接用同一个状态机，所以写引擎的 agent 不装输入法也能在终端里试、跑检查、回放输入记录，自己闭环——这是"面向 vibe coding"的关键。

## 考虑过的做法

- **只靠真实输入法试**：agent 无法自如地往别的应用里打字，每轮都得人来试。
- **只做改文件自动重启 + 日志**：好一点，但仍要人来试。

## 后果

- 状态机可以单独做完整的自动测试，跨应用测试矩阵只需覆盖那层薄外壳。
- 新的按键行为必须写进状态机，不能直接写在 macOS 那层，否则命令行版和输入法会不一致。
