# 引擎在沙盒里运行，只放行引擎说明里声明的能力

打字引擎天生能看到输入时的每个键和前文，等于一个键盘记录器；为了让分享别人的引擎也安全，壳用 macOS 自带的 Seatbelt（`sandbox-exec`）运行每个引擎。默认：不能联网、只能写自己的引擎数据目录（引擎文件夹本身只读，免得引擎改自己的引擎说明、给自己加权限）、读文件不限（Python、模型文件可直接用）、不能用麦克风/摄像头/屏幕。引擎要更多，就在所需权限里声明，比如"联网：仅本机"或"麦克风"。

这让所需权限从"说明"变成"约束"：没声明联网的引擎，想把按键发出去也做不到。也弥补了系统权限只能整体授给壳的缺口（见 ADR 0005）。

## 考虑过的做法

- **不约束，引擎是用户自己装的可信代码**：最简单，但装别人的引擎就等于装了键盘记录器。
- **只默认禁止联网**：挡住主要风险，但声明了麦克风和没声明的引擎能力上没区别。

## 后果

- 写引擎时会碰到"被沙盒拦了"；壳必须把被拦的操作和对应该补的声明清楚地报出来，让 agent 能照着改。
- Seatbelt 已有 `device-microphone`、`device-camera`、`network-outbound` 等规则；屏幕录制能否这样拦，实现时要验证。

## 实测后的修订（2026-10-08）

research/seatbelt 的实测推翻了"以允许为底、定向禁止"：那样写，剪贴板、LaunchServices（打开网址）、AppleEvents、窗口服务、音视频、隐私授权查询等 12 个系统服务全都还能访问。所以改为**默认全拒 + 导入 Apple 的 `system.sb`**，再按声明放开。具体：

- 模板固定（`Sources/LuokeShell/SandboxTemplate.swift`），每个引擎的声明用 `-D` 参数传入，不拼接规则文本。
- 屏幕录制没有对应的 Seatbelt 操作，靠不放行抓屏所需的系统服务来拦；真实抓屏、真实录音未实测。
- `network: local` 能连本机所有服务（包括本地代理，等于能上外网），因此增加 `local_ports` 限定端口；unix socket 任何档位都不放行。
- 读：输入记录、别的引擎的数据、壳的设置不可读；其余不限。
- 违规从统一日志读取（`log stream`，按规则里的 `LUOKE[<引擎>]` 标签认领，子进程也算得上），`check` 和 `try` 会报告。
- 风险：`sandbox-exec` 已被 Apple 标为弃用，`system.sb` 是私有文件；规则编译失败时会拒绝启动（失败即关闭），不会无保护运行。
- 2026-10-09 增加 `gpu` 声明：引擎里跑本地模型要用 Metal。放行 Apple 的 `system-graphics` 规则、Metal 编译服务和它在用户缓存目录下的几个缓存子目录；这一节放在屏幕录制之前，屏幕录制的禁止规则仍然优先。

## 修订（2026-10-16）

- 读不限，但钥匙和凭据（`~/.ssh`、`~/.gnupg`、`~/.aws`、钥匙串等）、浏览器和邮件的数据、shell 历史对所有引擎都不可读（luokelabs/luoke-ime#6）。
- 第三方引擎不能声明联网、GPU 和额外的写入位置，并且要用户确认才启用，见 ADR 0012。上面写的 `network: local`、`local_ports`、`gpu` 现在只对随输入法发布的引擎有意义。
