# 先快后好：引擎可以补发，壳用三条规则决定何时换候选

引擎对一次询问可以先给一份快的答复，再补发更好的，并标明后面还有没有；不用模型的引擎只答复一次。壳按三条规则处理（沿用知音验证过的做法）：先等约 50 ms 再画候选窗，补发在这之内到就直接画它，避免每键闪两次；补发来晚了就替换，但用户已移动高亮或翻页则不替换，避免在手指底下换词；按空格时若补发还在路上，最多再等 150 ms，等不到就上屏现有首选。

这些等待看起来像人为延迟，是有意的：带模型的引擎重排一次中位数约 135 ms（M4），一问一答会让打字发粘，直接替换又会闪烁、误选。

## 考虑过的做法

- **一问一答**：引擎最简单，但带模型的引擎只能等模型算完再回。
