# 第三方引擎要用户确认才启用，一律不能联网

2026-10-16 定（luokelabs/luoke-ime#6，团队成员审代码时提的）。

原来引擎说明里的 `permissions` 自己写自己的：写了 `network: any` 就能联网，放进引擎目录就自动启动、没设当前引擎时会被自动选中，同名的会盖过自带的引擎、还按文件夹名继承自带那份的记忆同意；沙盒读不限，`~/.ssh` 这类也读得到。输入法看得到每个按键，合起来就是一个能把按键和家目录的文件发出去、用户却看不到任何提示的通道。

改成：

- **第三方引擎**（装在 `~/.luoke/ime/engines`、不是随输入法发布的）不能联网、不能用 GPU、只能写自己的数据目录；声明了就不启用。要用模型经主控的任务（同日定：第三方引擎只经主控的任务，不自己加载模型、不占 GPU）。
- 第三方引擎**用户确认了才启用**：系统确认框列出它能做什么、不能做什么，默认"不启用"。确认绑在引擎说明里和权限有关的内容的指纹上，变了要重新确认；不自动选中第三方引擎；同名的确认前不代替自带的，记忆同意按"标识@指纹"记、不继承。
- 沙盒对所有引擎挡住钥匙和凭据、浏览器和邮件数据、shell 历史的读取。
- 没允许"保存到本机记忆"时，上屏、删改、忘掉不转给任何个人化组件（自带的原来只放内存，第三方的可以自己存下来）。

## Considered Options

- **第三方引擎也能声明联网，启用时让用户确认**：确认框挡不住"点了就算"；数据留在本机（顶层 ADR 0007）和"模型归主控"都说明第三方引擎不需要联网。以后真有需要再开一种要用户确认的档位。
- **确认绑在整个引擎文件夹的内容上**：改一行代码就要重新确认，写引擎的人每次保存都弹窗；沙盒只放行声明过的，代码改了能力也不会变，所以只绑和权限有关的内容。
- **读改成白名单**：Python、Homebrew、模型文件散在各处，白名单会让大量正常引擎跑不起来；不能联网以后，读到的东西出不去，挡住最敏感的几类就够。

## Consequences

- 开发时装在引擎目录里的自带引擎副本（比如改着的 xiaohe）也是第三方引擎：第一次要确认，改了权限要再确认；本来就不联网，不受影响。
- 卸载输入法时删 `~/.luoke/ime` 会连确认记录一起删。
- 第三方引擎经转问交给个人化组件和主控的前文仍然会到它们那里，这是打分、联想要用的；它们都在本机。

## 修订（2026-10-16 晚，只读审查后）

- 引擎转问个人化组件只能问 `score`、`ping`（`predict` 只有壳能问：它用的是记忆里用户写过的历史）；安全输入时一律不转，第三方的个人化组件在"禁止记录"的应用里、暂停时、没允许记忆时也收不到转问和联想请求。
- 第三方引擎的沙盒里没有系统共用的 TemporaryItems（它能抢先改别的应用、壳自己正在原子保存的文件）；壳保存设置改成在同一目录用 O_EXCL 建临时文件再改名。
- 所有引擎不能建符号链接（防止把 mem.db 的 -wal / -shm 换成链接；luoke-mem 0.15.8 打开前也核对），读不到别的引擎的临时目录；挡读名单补上更多浏览器、应用容器、各种历史和开发工具的凭据。
- `engine.json` 不跟随链接读一次，解析和指纹用同一份字节；指纹加上 `name`、`input_keys`（改名冒充自带引擎要重新确认）。
- 和自带引擎同名的第三方引擎用自己的数据目录（`<标识>.third-party`）。
- 还没做：壳被 SIGTERM 时不听话的引擎可能留成孤儿（不能联网，危害有限），以后在壳启动时清旧的进程组。
