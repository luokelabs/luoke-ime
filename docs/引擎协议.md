# 引擎协议（第 1 版，草案）

壳和引擎之间的全部约定。术语见 [CONTEXT.md](../CONTEXT.md)，背后的取舍见 [adr/](adr/)。

## 基本约定

- 引擎是壳的子进程（ADR 0002）。壳经标准输入发消息，引擎经标准输出回消息，**每行一个 JSON 对象**，UTF-8，以 `\n` 结尾。
- **标准输出只能写协议消息。** 日志、调试信息一律写标准错误；壳保留最近 200 行，引擎崩溃时把最后几行放进通知。标准输出出现非 JSON 的行，算协议错误。
- 每条消息都有 `type` 字段。**双方都必须忽略不认识的 `type` 和不认识的字段**，这样协议可以加东西而不打破旧引擎。
- 字段名用英文小写加下划线，方便任何语言、任何 agent 直接写。
- 不用 JSON-RPC：它规定一个请求只有一个响应，而补发要求同一次询问可以有多个答复（ADR 0003）。

### 引擎的运行环境

| 项 | 值 |
|---|---|
| 工作目录 | 引擎文件夹（只读） |
| `PATH` | 壳启动时从用户的登录 shell 读到的 `PATH`，和在终端里一样 |
| `LUOKE_IME_DATA` | 引擎数据目录，唯一可写的地方 |
| `LUOKE_IME_PROTOCOL` | `1` |
| `PYTHONPYCACHEPREFIX` | 引擎数据目录下的 `pycache`，让 Python 的字节码缓存落在可写的地方 |
| `LUOKE_IME_MEMORY` | 螺壳记忆文件（`~/.luoke/mem.db`）的路径，只给声明了 `memory` 的个人化组件 |
| 沙盒 | 见下文"所需权限" |

壳要引擎退出时关闭它的标准输入；1 秒后还没退出就强制结束。

## 引擎说明：`engine.json`

放在引擎文件夹根目录。文件夹名就是引擎的标识。

```json
{
  "protocol": 1,
  "name": "小鹤双拼",
  "kind": "typing",
  "run": ["python3", "engine.py"],
  "input_keys": "abcdefghijklmnopqrstuvwxyz",
  "context": 200,
  "app": false,
  "feedback": true,
  "permissions": { "network": "local" },
  "options": { "...": "见下文" }
}
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `protocol` | 整数 | 必填 | 协议版本。壳不支持时拒绝启动该引擎并说明原因。 |
| `name` | 字符串 | 必填 | 菜单和设置里显示的名字。 |
| `kind` | `"typing"` / `"hotkey"` / `"personal"` | 必填 | 打字引擎、快捷键引擎，或个人化组件（见"个人化组件"）。 |
| `run` | 字符串数组 | 必填 | 启动命令。第一项是绝对路径就直接用；含 `/` 的相对路径（如 `./run.sh`、`bin/engine`）相对引擎文件夹；不含 `/` 的按 `PATH` 查找。写 `luoke-python` 时用螺壳主控带的 Python（3.12，完整标准库，没有第三方包；luoke-core V1 §8 的约定），壳在后面加 `-B -E -s -u`；没装主控时用 PATH 里的 `python3`。 |
| `input_keys` | 字符串 | 打字引擎必填 | 输入键：会进入输入串的字符。输入键优先于壳的选词键，比如声明了数字，数字就不再用来选词。大写字母另有一条：只在输入串开头、或者大写开头的输入串里收（打英文，比如 GitHub）；小写开头的输入串里按 Shift+字母，壳照旧收尾上屏再放行。 |
| `punctuation` | 对象 | 壳的默认表 | 标点表，见下文。 |
| `context` | 整数 | `0` | 前文最多读多少个字（不超过 2000）；`0` 表示壳根本不读。 |
| `app` | 布尔 | `false` | 是否要知道当前应用（bundle id）。 |
| `feedback` | 布尔 | `false` | 是否接收反馈消息。 |
| `forget_all` | 布尔 | `false` | 引擎自己会记住学到的东西（比如改选过的词），能整个清掉：菜单的输入方案一组里因此有"清掉「引擎名」学到的词…"，设置「记忆」页的「「引擎名」的词」里也有「全部清掉」，用户确认后壳发 `forget_all`（见"反馈"）。 |
| `hotkey` | 对象 | 快捷键引擎必填 | 见"快捷键引擎"。 |
| `asks` | 字符串数组 | `[]` | 会经壳向谁转问：`"personal"`（个人化组件）、`"hub"`（主控），见"转问"。 |
| `permissions` | 对象 | 全部关闭 | 所需权限，见下文。 |
| `options` | 对象 | 无 | 引擎选项界面，见下文。 |

### 标点表

键是按下的字符，值是上屏的文字；值写成两项的数组表示成对符号，壳在两项间交替。

```json
"punctuation": {
  ",": "，", ".": "。", "?": "？", "!": "！", ":": "：", ";": "；",
  "\\": "、", "(": "（", ")": "）", "[": "【", "]": "】", "<": "《", ">": "》",
  "~": "～", "^": "……", "_": "——", "$": "￥", "`": "·",
  "\"": ["“", "”"], "'": ["‘", "’"]
}
```

- 不写 `punctuation`：用壳的默认表，即上面这张（实现时逐项和系统简体拼音核对）。
- 写了：**整张替换**默认表；没列出的符号直接放行。写 `{}` 就是全部半角。
- 数字后面的 `.` `:` 保持半角、`,` 看下一个键再定半角还是全角，这类和上下文有关的规则由壳处理，不在表里。`{` `}` 默认上屏「」（和系统简体拼音一样），用户在设置里关掉之前，这两个键按壳的设置上屏、盖过表里的写法。

### 所需权限

壳用 Seatbelt 沙盒运行每个引擎（ADR 0006），只放行声明过的能力。

```json
"permissions": {
  "network": "none",
  "local_ports": [],
  "write": [],
  "microphone": false,
  "camera": false,
  "screen": false,
  "gpu": false,
  "memory": false
}
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `network` | `"none"` / `"local"` / `"any"` | 不联网 / 只连本机（比如本地模型服务）/ 任意联网。`local` 只放 127.0.0.1 和 ::1 的 TCP、UDP，不放 unix socket，也不能做名称解析（用 `127.0.0.1` 而不是 `localhost`） |
| `local_ports` | 端口数组 | 只能和 `"network": "local"` 一起写（否则引擎说明不合法）：只许连这些本机端口（最多 8 个）。不写就是本机所有端口——注意本机上的代理也算，等于能上外网 |
| `write` | 路径数组 | 引擎数据目录和临时目录之外，额外可写的位置；必须是绝对路径或以 `~/` 开头，不能和壳自己的目录 `~/.luoke/ime` 重叠。路径本身是符号链接时不跟随（只解析上级目录），要写的是链接指向的地方就直接声明那里 |
| `microphone` `camera` `screen` | 布尔 | 需要系统授权的设备；用户启用引擎时壳才向系统申请（ADR 0005） |
| `gpu` | 布尔 | 用 GPU（Metal），比如在引擎里跑本地模型。不需要系统授权 |
| `memory` | 布尔 | 读写螺壳的记忆（`~/.luoke/mem.db` 和 SQLite 的 `-wal` `-shm` `-journal`），路径在环境变量 `LUOKE_IME_MEMORY`。只有个人化组件能声明。光声明还不够：记忆记录要开着（全局设置里的"记录输入内容到记忆"；自带的个人化组件默认开，第三方的要用户另外打开），关着时沙盒不放行记忆文件、也不给路径，上屏、删改、忘掉也不转给它。记忆文件本身是符号链接时不跟随 |

`network`、`local_ports`、`gpu`、`write` 只有随输入法发布的引擎能用；第三方引擎声明了就不启用（见下面的"第三方引擎"）。

读文件基本不受限制，但输入记录、别的引擎的数据目录、壳的设置文件和 `~/.luoke` 下螺壳其他工具的数据（比如记忆）不可读；钥匙和凭据（`~/.ssh`、`~/.gnupg`、`~/.aws`、钥匙串、`~/.netrc` 这类）、浏览器和邮件的数据、shell 历史，任何引擎都不可读。不论声明了什么，引擎文件夹和 `~/.luoke/ime` 都不可写（自己的数据目录除外）。被沙盒拦下时，壳报告被拦的操作和应补的声明。

### 第三方引擎

装在 `~/.luoke/ime/engines` 里、不是随螺壳输入法发布的引擎（luokelabs/luoke-ime#6）：

- **不能联网**，也不能用 GPU、写自己数据目录以外的地方：`permissions` 里写了 `network`（`none` 以外）、`gpu`、`write`，就不启用，菜单里写明原因。要用模型，经壳转问螺壳主控的通用原语（见"转问"：打分 `score`、续写 `continue`），模型由主控加载、全机一份；怎么截、怎么挑、什么算有把握，引擎自己定。
- **用户确认了才启用**：第一次启用时，壳弹系统的确认框，写明它装在哪、不是随螺壳发布的、启用以后能做什么（看到按键、读多少字前文、知道当前应用、收反馈、麦克风等）和不能做什么。确认绑在引擎说明里和权限有关的内容上（`kind`、`run`、`permissions`、`asks`、`context`、`app`、`feedback`、`forget_all`、`hotkey`），这些变了要重新确认；只改代码、选项、名字不用。
- **不会被自动选中**；和自带的引擎同名的，确认前照旧用自带的那份，确认后才代替它，也不继承自带那份的记忆同意。
- 第三方的个人化组件同样要确认；读写记忆还要用户另外允许。它在"禁止记录"的应用里、暂停时、没允许记忆时收不到引擎的转问和壳的联想请求。
- 沙盒里没有系统共用的 TemporaryItems：Swift 的 `Data.write(options: .atomic)` 这类会在那里建临时副本的写法会被拦，自己的临时文件请放在 `TMPDIR` 或 `LUOKE_IME_DATA` 里。
- 和自带引擎同名的，数据目录另起一个（`<标识>.third-party`），读写不到自带那份的数据。
- `engine.json` 必须是普通文件（是符号链接就不认）。

所有引擎（自带的也一样）都不能建符号链接，读不到别的引擎的临时目录。

### 引擎选项

用 A2UI v0.9.1 的组件格式描述，组件只能来自壳的组件目录（ADR 0008）：`Text`、`CheckBox`、`ChoicePicker`、`Slider`、`TextField`、`Button`、`Divider`、`Row`、`Column`。`components` 是扁平列表，必须有一个 `id` 为 `root`；`data` 是默认值，组件用 `{"path": "/…"}` 绑定到它。

```json
"options": {
  "components": [
    { "id": "root", "component": "Column", "children": ["learn", "fuzzy", "model"] },
    { "id": "learn", "component": "CheckBox", "label": "从我的修改里学习", "value": { "path": "/learn" } },
    { "id": "fuzzy", "component": "CheckBox", "label": "模糊音（z/zh、c/ch、s/sh）", "value": { "path": "/fuzzy" } },
    { "id": "model", "component": "ChoicePicker", "label": "模型",
      "options": [ { "label": "小（更快）", "value": "0.8b" }, { "label": "大（更准）", "value": "2b" } ],
      "value": { "path": "/model" } }
  ],
  "data": { "learn": true, "fuzzy": false, "model": ["0.8b"] }
}
```

- 用户改过的值存在引擎数据目录的 `options.json`，结构和 `data` 相同；直接改这个文件，效果和在设置页里改一样。值一变，壳重启引擎。
- 注意 `ChoicePicker` 的值按 A2UI 规定是字符串数组，单选也一样。
- 壳还会给打字引擎加一个选项 `fuzzy`：用户勾选的模糊音组，比如 `["z_zh", "in_ing"]`，关着时是空数组。它来自壳的设置，盖过引擎说明和 `options.json` 里的同名值；上面例子里的 `fuzzy` 只是组件写法的示例。不支持的引擎忽略它。
- 第一版只画静态界面；`Button` 的动作和运行中推送界面更新留到以后（保留消息类型 `ui`）。

## 打字引擎

### 壳 → 引擎

**`hello`**：引擎启动后壳发的第一条消息。引擎可以忽略。

```json
{"type": "hello", "protocol": 1, "options": {"learn": true, "fuzzy": false, "model": ["0.8b"]}, "data_dir": "/Users/me/.luoke/ime/data/flypy"}
```

**`query`**：询问。输入串每变一次发一次。

```json
{"type": "query", "id": 42, "input": "buzd", "context": "今天我", "app": "com.tencent.xinWeChat"}
```

| 字段 | 说明 |
|---|---|
| `id` | 递增整数。新的询问发出后，旧的就作废。 |
| `input` | 剩余的输入串（已选部分之后的那些键）。 |
| `context` | 前文，只在声明了 `context` 时出现。已选部分接在它末尾，上例里的"我"就是刚选定的已选部分。 |
| `app` | 只在声明了 `app: true` 时出现。 |

### 引擎 → 壳

**`answer`**：答复。

```json
{"type": "answer", "id": 42, "display": "bu zd", "candidates": [
  {"text": "不知道", "consume": 4},
  {"text": "不", "consume": 2},
  {"text": "步", "consume": 2, "note": "bù"}
], "more": true}
```

| 字段 | 说明 |
|---|---|
| `id` | 对应哪次询问。不是最新询问的答复，壳直接丢弃。 |
| `display` | 显示串。省略时壳显示原始输入串。 |
| `candidates` | 候选，按引擎希望的顺序。可以为空。 |
| `candidates[].text` | 候选文字。 |
| `candidates[].consume` | 用掉输入串开头的几个键，`1` 到 `input` 的长度（按字符数）。 |
| `candidates[].note` | 注释，可选，候选窗里用灰色小字显示。约定：补发里被慢的那一路改过的候选写 `✦`（壳等补发时显示的也是 ✦）。 |
| `more` | `true` 表示后面还会补发；省略即 `false`。 |
| `autocommit` | `true` 时壳立即选中首选，用于五笔四码唯一这类情况。可选。 |

同一个 `id` 可以答复多次，后一次整体替换前一次（先快后好，ADR 0003）。`more` 只是告诉壳按空格时值不值得等：不标 `more` 之后也还可以再补发（比如引擎空下来后又算出了更好的），壳照样替换，只是按空格时不会等它。壳何时画、何时替换，见[设计文档](设计.md#先快后好的显示规则)。

建议：首选尽量用掉整个输入串（整句），这样空格、标点、切走都能一次上屏完整内容。

### 反馈（只在声明了 `feedback: true` 时发送）

系统处于安全输入（密码框等）时、用户暂停了记录时、当前应用设了"不记录"时，壳不发下面这三种反馈：用户要的是哪里都不留痕迹，引擎自己的学习数据也不记。询问照常发（出候选要用）。

**`committed`**：一次上屏。

```json
{"type": "committed", "id": 7, "text": "我不知道", "auto": false, "context": "今天",
 "pieces": [
   {"input": "wo", "text": "我", "index": 0, "top": "我"},
   {"input": "buzd", "text": "不知道", "index": 0, "top": "不知道"}
 ]}
```

| 字段 | 说明 |
|---|---|
| `id` | 上屏的序号，`deleted` 用它指向这次上屏。 |
| `text` | 实际上屏的整段文字（壳在中英文之间自动加的空格不算在内）。 |
| `auto` | `true` 表示这是切走时的自动上屏，不是用户确认的。 |
| `context` | 开始输入时的前文（不含这次的已选部分），按声明给出。 |
| `pieces` | 每一段：用掉的键、选中的文字、选的是第几个候选（从 0 起）、当时的首选是什么。按回车上屏的原始字母，这一段写成 `{"input": "buzd", "text": "buzd", "raw": true}`。以词定字（输入中按 `[` `]`）只取了候选的第一个或最后一个字时，这一段多一个 `"char": "first"` 或 `"last"`，`text` 是那个字：它不是这串键的意思，别拿它学。 |

**`deleted`**：上屏后紧接着连续按了几次退格。遇到别的键、换输入框、换应用，或 5 秒内没再按退格时，壳发出这条。

```json
{"type": "deleted", "after": 7, "count": 3, "followed_by": "，"}
```

`followed_by` 只在壳紧跟着这次上屏又上屏了别的文字时出现（输入中按标点：先收尾上屏，再上屏标点）。退格会先删到它，所以真正删掉的上屏文字是 `count` 减去它的长度。

**`forget`**：用户在候选窗里高亮一个候选按了 Shift+⌫。

```json
{"type": "forget", "input": "xkyy", "text": "行云", "context": "今天的"}
```

壳不报告其他任何非输入时的按键。

**`forget_all`**：用户在菜单里点了"清掉「引擎名」学到的词…"或在设置里点了「全部清掉」、在确认框里确认了。只发给声明了 `"forget_all": true`、正在运行的引擎，不受安全输入、暂停记录、"不记录"的应用影响（这是用户的要求，不是学习）。没有答复。

```json
{"type": "forget_all"}
```

清掉什么由引擎定，但要真的从文件里删掉、不留备份；用户要求忘掉的名单可以留着（不然忘掉的候选会再冒出来）。自带的小鹤、全拼清掉改选过的词，留着忘掉的名单。

声明了 `forget_all` 的引擎还要：

- 在数据目录里维护 `forgotten.json`：`{"forgotten": [{"input": "wo", "text": "窝"}], "older": 0}`，列出用户忘掉过的候选（`older` 是列不出原文的个数）。壳的设置窗口照它列"忘掉过的词"。
- 收 `unforget`：用户在设置窗口里撤销忘掉，引擎让它重新出现、更新 `forgotten.json`。

```json
{"type": "unforget", "input": "wo", "text": "窝"}
```

## 快捷键引擎

引擎说明里声明快捷键：

```json
"kind": "hotkey",
"hotkey": {"key": "right_command", "mode": "hold"}
```

- `key`：第一版支持 `right_command`、`right_option`、`right_control`。
- `mode`：`hold` 是按住期间生效、松开结束，`press` 是按一下开始、再按一下结束。
- `hold` 模式下，按住超过 150 ms、而且期间没按别的键才算触发；期间按了别的键，就当作普通组合键（比如右 ⌘C），不触发。
- `arm`（可选，默认 `false`，只用于 `hold`）：按下那一刻就发 `arm`，让引擎先开始准备（语音：开始录音，不然开头的字会丢）；确认是按住了再用同一个 `id` 发 `start`，不是就发 `cancel`。声明了 `arm` 的引擎随壳启动，不等第一次按键。
- 只有壳是当前输入法时快捷键才有效：输入法收不到别的输入法下的按键。
- 密码框（安全输入）里快捷键引擎不触发，也不发 `arm`。

### 壳 → 引擎

```json
{"type": "arm", "id": 3}
{"type": "start", "id": 3, "context": "会议纪要：", "app": "com.apple.Notes"}
{"type": "stop", "id": 3}
{"type": "cancel", "id": 3, "reason": "esc"}
```

- `arm`：只发给声明了 `arm` 的引擎，按下时就发。之后要么是同一个 `id` 的 `start`（确认按住了），要么是 `cancel`（`short`：没按够 150 ms 就松开了；`key`：按了别的键、别的修饰键或鼠标，是组合键；`focus`：切走了）。收到 `cancel` 就丢掉准备好的东西（比如录到的音频）。
- `start`：触发。若当时正在输入，壳先收尾上屏，再发 `start`。
- `stop`：用户松开（`hold`）或再按一次（`press`），请引擎给出最终结果。
- `cancel`：会话结束，之后的消息作废。`reason` 是 `esc`（用户取消，什么都不上屏）、`key`（用户按了别的键，壳已把最近一次 `show` 的文字上屏）、`focus`（切走了，同 `key`）或 `timeout`（`stop` 后迟迟没有结果，同 `key`）。

### 引擎 → 壳

```json
{"type": "show", "id": 3, "text": "今天下午三点"}
{"type": "show", "id": 3, "text": "今天下午3点开会。", "hint": "整理中…"}
{"type": "level", "id": 3, "level": 0.6}
{"type": "commit", "id": 3, "text": "今天下午三点开会。"}
{"type": "end", "id": 3}
```

- `show`：更新光标处的显示串，可以发任意多次。可选的 `hint` 是光标旁的提示（比如语音松开后终稿出来、正在整理时的「整理中…」）；不给时壳按自己的规矩提示（见下面「声明了麦克风的引擎」）。可选的 `listening`（`true` / `false`，不给时算 `true`）：声明了麦克风的引擎用它说话筒是不是真的开始收音了，`false` 时壳显示「准备中…」。
- `level`（可选，声明了麦克风的引擎用）：这会儿的音量，0（只有底噪）到 1，超出的壳夹到这个范围。按住在听时壳把红点换成三根跟着它伸缩的音量条；没发过就照旧画红点。自带的语音每 0.1 秒发一次。
- `commit`：上屏这段文字，会话结束。
- `end`：什么都不上屏，会话结束。
- `stop` 之后 10 秒内没有 `commit` 或 `end`，壳按 `timeout` 取消。
- 声明了麦克风的引擎（语音），壳在光标旁一直提示在什么状态：话筒还没开始收音时（引擎发了 `listening: false`）是一个轻轻闪的黄点和「准备中…」，按住时是一个一跳一跳的红点（引擎发了 `level` 就是跟着音量伸缩的三根红条）和「录音中」，`stop` 之后是慢慢呼吸的灰点和「整理中…」（引擎用 `hint` 给了提示就用它，比如「音量过低，未识别到语音」）。按住期间的显示串是未确认的文字，松开后由 `commit` 一次上屏（长段听写也是这样，ADR 0016）。

## 个人化组件

一种特殊的引擎（ADR 0010）：同一时间一个，壳把所有引擎的上屏、上屏后的退格和忘掉转给它，别的引擎可以经壳转问它。它把这些写进螺壳的记忆，再给打分、联想、热词加上个人化（用户自己写过的、主控的模型，以后加上记忆归纳出的常用说法）。从打的字里归纳关于用户的理解是螺壳记忆的事（顶层 ADR 0005），个人化组件只写记录、读理解。

```json
{
  "protocol": 1,
  "name": "个人化",
  "kind": "personal",
  "run": ["luoke-python", "personal.py"],
  "context": 200,
  "app": true,
  "asks": ["hub"],
  "permissions": { "network": "none", "memory": true }
}
```

- 引擎目录里有几个 `kind` 为 `personal` 的，壳用文件夹名排第一的那个。随壳启动、常驻，崩溃了照常重启和停用。
- 不写 `input_keys`、`hotkey`、`feedback`（它总是收到下面这些事件）；`context` 是每次上屏带多少字前文，`app` 是要不要知道应用。
- 规则比别的引擎严，引擎说明不合规矩就不启动：**不能联网**（`network` 只能是 `none`）；不能声明麦克风、摄像头、屏幕录制；只有它能声明 `memory`；不能转问自己（`asks` 里只能有 `hub`）。
- **壳不转的时候**：系统处于安全输入（密码框等）时、用户在菜单里暂停了记录时、当前应用设了"不记录"时，这些事件根本不发给它。

### 壳 → 个人化组件

**`committed`**：一次上屏。比打字引擎收到的多三个字段：

```json
{"type": "committed", "id": 12, "text": "我不知道", "auto": false, "context": "今天", "kind": "typing", "source": "xiaohe",
 "app": "com.tencent.xinWeChat", "pieces": [{"input": "wo", "text": "我", "index": 0, "top": "我"}, {"input": "buzd", "text": "不知道", "index": 1, "top": "不只道"}]}
```

| 字段 | 说明 |
|---|---|
| `id` | 个人化组件这边的上屏序号（和打字引擎收到的不是同一套号）。 |
| `kind` | `typing`：打字引擎的上屏，带 `pieces`（字段同打字引擎的反馈，`index` 不是 0 就是在候选里改选了）；`punctuation`：壳按标点表上屏的标点；`hotkey`：快捷键引擎（比如语音）的上屏；`english`：英文模式下敲的一段（按键直接交给应用，壳按按键攒的，退格去掉最后一个字，回车、挪光标、点鼠标、切走、切回中文时收尾，`source` 是 `english`，终端里不攒；见 ADR 0017）。后三种没有 `pieces`。 |
| `source` | 出字的引擎（文件夹名）。标点算当前打字引擎的；英文模式的是 `english`。 |
| `context` | 开始输入（快捷键引擎是触发）时光标前的文字，按它声明的字数；标点没有。 |
| `app` | 只在声明了 `app: true` 时出现。 |
| `auto` | 同打字引擎：切走时的自动上屏。快捷键会话因切走、超时而把最后的显示串上屏时也是 `true`。 |

**`deleted`**：打字引擎的上屏后紧接着的连续退格，字段同打字引擎的，`after` 指向个人化组件这边的序号。

**`forget`**：同打字引擎的，另带 `source`。

**`ask`**：转来的转问，见下一节。

### 个人化组件提供的方法

| 方法 | 参数 → 结果 | 用途 |
|---|---|---|
| `ping` | → `{"ok": true}` | 试通 |
| `score` | `{"context", "candidates": [...]}` → `{"logprobs": [...], "slow"?}`（引擎能问的只有它和 `ping`；`predict` 用的是用户写过的历史，只有壳能问） | 每个候选接在前文后面的对数概率（小鹤、全拼引擎重排用）。`slow` 为 true：这台机器上打分慢（主控按实测标的），引擎宜少给候选。`candidates` 为空时答空的 `logprobs`，引擎用它试试能不能打分。模型还在加载答 `not_ready`，没有模型答 `unavailable`，排队太久答 `expired`，算超时答 `timeout` |
| `predict` | `{"context", "app"?}` → `{"candidates": [...]}` | 联想：前文后面接着写的几种说法，最多 5 个，没有就是空的。壳上屏后自己来问（`from` 是 `shell`） |
| `hotwords` | `{"limit"}` → `{"words"}`：记忆里的常用说法（term），确认过的、有把握的在前，同档里最近用过的在前；标了敏感类别的、否掉的、被换掉的不给，没开记忆时是空的 | 给语音；只有随输入法发布的引擎能问，第三方引擎答 `not_allowed` |

还没做的方法答 `not_implemented`，不认识的答 `unknown_method`。

## 转问

引擎经壳向个人化组件（以后还有主控）提的请求。壳只看 `to` 和引擎说明里的 `asks`，不看 `method`、`params` 和答复的内容。

**引擎 → 壳**：

```json
{"type": "ask", "id": 5, "to": "personal", "method": "score", "params": {"context": "今天", "candidates": ["天气", "天七"]}}
```

`id` 是引擎自己编的号（整数），`params` 是对象，可以省略。

**壳 → 个人化组件**：壳换成自己的号，加上发问的引擎：

```json
{"type": "ask", "id": 31, "from": "xiaohe", "method": "score", "params": {"context": "今天", "candidates": ["天气", "天七"]}}
```

**个人化组件 → 壳 → 发问的引擎**：每个 `ask` 都要用同一个 `id` 答一条 `reply`，`result`（任意 JSON）和 `error` 恰好有一个；壳把号换回发问时的号转回去：

```json
{"type": "reply", "id": 5, "result": [-1.2, -9.8]}
{"type": "reply", "id": 5, "error": {"code": "not_implemented", "message": "……"}}
```

壳自己也会答错误（不转出去）：

| `error.code` | 什么时候 |
|---|---|
| `not_allowed` | 引擎说明的 `asks` 里没有这个 `to` |
| `unavailable` | 个人化组件没装、没在运行或停用了；转出去以后它退出了；主控没在运行（连不上它的 socket） |
| `bad_request` | `to` 不认识 |

- **转问主控**（`to: "hub"`）：只有壳连主控（luoke-core，HTTP/1.1 跑在 Unix socket 上，线上格式见 luoke-core `docs/V1.md` §2，对外约定版本 1），请求头带 `X-Luoke-Accessory: luoke-ime/<版本>`。壳认的方法：
  - `score`：`params` 是 `{"task", "context", "candidates"}`，`task` 必须是输入法自己的任务（`luoke-ime.` 开头，比如 `luoke-ime.rerank`），转成 `POST /tasks/<task>/v1/score`；`result` 是主控的答复 `{"logprobs", "model", "cache_hit", "ms"}`。
  - `predict`：`params` 是 `{"task", "context", "k"?, "n"?}`，转成 `POST /tasks/<task>/v1/predict`；`result` 是 `{"continuations": [[文字, 总对数概率, 第一个 token, 它的对数概率], ...], "model", "cache_hit", "ms"}`。
  - `tasks`：`GET /tasks`，`result` 原样给（任务状态和任务参数）。
  - `warmup`：`params` 是 `{"task", "lease_id"?}`，转成 `POST /warmup`；带上次答复里的 `lease_id` 是续期（语音开着时用它让转写模型保温）。
  - `generate`：生成，`params` 是 `{"task", "messages", "response_format"?, "priority"?}`，转成 `POST /tasks/<task>/v1/chat/completions`（主控一律流式，壳等整段生成完拼起来），`result` 是 `{"text", "model"}`。`priority` 是 `user-waiting`（默认）或 `background`，壳放进 `X-Luoke-Priority` 头。提示词由发问的引擎自己给，壳不看。语音的整理用任务 `luoke-ime.tidy`。
  - `transcribe`：语音转写，`params` 是 `{"task", "session", "seq", "audio", "want", "context"?}`，转成 `POST /tasks/<task>/v1/transcribe`（任务 `luoke-ime.transcribe`）。一次听写一个会话，`audio` 是上次以后新录的一块（base64，PCM16LE 16 kHz 单声道），`want` 是 `none`（只追加）、`draft`、`final`、`cancel`；会话丢了（`session_lost`）从 `seq` 0 重送整段，草稿被更新的请求顶掉时答 `superseded`。字段的意思以 luoke-core 的 V1 §2 为准。
  主控拒绝时，`error` 照搬主控的 `code`、`message`、`retry_after`（比如模型在加载：`not_ready`，`retry_after` 2）；连不上答 `unavailable`。现在只有个人化组件声明了 `"asks": ["hub"]`。第三方引擎要用模型也走这条（引擎自己不能联网、不能用 GPU），用输入法的任务：打分用 `luoke-ime.rerank`，续写用 `luoke-ime.predict`。
- **谁能转问个人化组件**：它的答复里有用户的个人数据，所以声明了 `"asks": ["personal"]` 的引擎不能联网出去：`network` 只能是 `none`，或者 `local` 并用 `local_ports` 限定端口（本机所有端口里可能有代理）。
- **等多久由发问的引擎定**：壳不替它计时。不再等的转问（比如新的询问来了），晚到的 `reply` 引擎自己丢掉；所以每次转问用新的号。壳只把转出去 30 秒还没答复的转问从表里清掉。
- 转问不经过壳的主线程：按空格时壳在等补发，打字引擎的转问照样能走完。
- 答复只转给发问的那一代进程：引擎重启了，旧转问的答复不会发给新进程；也只认转给的那个个人化组件发来的、还在等的号，别的引擎发 `reply` 壳不理。

## 时间参数

| 项 | 值 |
|---|---|
| 收到首个答复前，等多久再画候选窗 | 50 ms |
| 按空格时补发还在路上，最多再等 | 150 ms |
| 按空格、数字、标点时一份答复都还没有，最多等到 | 卡死的时刻（询问后 1 s） |
| 一次询问多久没有任何答复算卡死 | 1 s |
| 上屏后停多久没有按键才问个人化组件联想 | 250 ms |
| 联想问出去多久没答复就不要 | 1 s |
| 多久内崩溃 3 次就停用（卡死被重启也算一次） | 1 分钟 |
| `hold` 快捷键按住多久算触发 | 150 ms |
| `stop` 后等最终结果 | 10 s |
| 关闭标准输入后等引擎退出 | 1 s |
| 转出去的转问在壳的表里最多留 | 30 s |

## 保留

- `ui`：引擎在运行中推送 A2UI 消息（界面更新、数据更新），以及壳把按钮动作发给引擎。第一版不实现。
