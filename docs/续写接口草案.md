# 续写接口草案（给 luoke-core 定稿，写进 V1 §2）

定下的：联想里"怎么截、挑哪几个、什么算有把握"归输入法，主控只提供通用的续写（顶层 ARCHITECTURE §2「模型推理」）。这一页是 luoke-ime 出的草案，luoke-core 定稿后以 V1 §2 为准。

## 现在的问题

`POST /tasks/luoke-ime.predict/v1/predict` 交回的是已经截好的文字：续到标点就停（标点表在主控里）、到 6 个字就切、开头是标点的丢掉。这些都是语言上的判断，碰到过的半截词（"结论和方法建"）就出在这里。

## 新端点：`POST /tasks/<任务名>/v1/continue`

通用的续写原语：前文后面最可能的 k 个开头（第一个 token 取概率最高的 k 个），各自往下贪心续，交回逐个 token 的文字和对数概率。停在哪由调用方给的条件定；主控不懂内容。

请求：

```json
{
  "context": "你看看它的一些",
  "k": 8,
  "max_tokens": 6,
  "stop": ["，", "。", "！", "？", "\n"]
}
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `context` | 是 | 前文。和打分一样的前文处理（主控在前面加同样的固定前缀，空前文也能续），和打分共用前缀快照 |
| `k` | 否 | 开头个数，缺省用任务参数；不得超过任务参数里的上限 |
| `max_tokens` | 否 | 每支最多续几个 token（含第一个），缺省用任务参数；不得超过上限 |
| `stop` | 否 | 停止串：某一支解码出来的文字里出现了其中任何一个，这支就停（停止串所在的那个 token 照样交回，由调用方决定要不要）。最多 64 个、每个最多 8 个字 |

答复：

```json
{
  "branches": [
    {"tokens": [{"text": "结论", "logprob": -1.2}, {"text": "和方法", "logprob": -0.9}, {"text": "建议", "logprob": -0.4}],
     "finish": "length"},
    {"tokens": [{"text": "特点", "logprob": -1.5}, {"text": "，", "logprob": -0.3}], "finish": "stop"}
  ],
  "model": "omlx-0.7.0-dev+qwen3.5-0.8b-base-4bit",
  "ms": 41,
  "cache_hit": true
}
```

- `branches`：k 支，按第一个 token 的对数概率从高到低。每支的 `tokens` 是逐个 token：`text` 是这个 token 加上以后解码文字多出来的那一段（增量解码；一个汉字被切成几个字节 token 时，前面几个的 `text` 是空的，最后一个带上整个字），`logprob` 是它的对数概率。拼起来就是这支的全文。
- `finish`：`stop`（碰到了停止串）、`length`（到了 `max_tokens`）、`eos`（模型结束）。
- 主控不丢、不并、不截任何一支，也不判断"开头是不是标点"。
- 错误码照 V1 §2：`not_ready`、`invalid_request`（`k`、`max_tokens` 超上限，`stop` 太多太长）等。不等待加载，和 predict 一样。

任务参数（配方里）：`k`、`max_tokens` 的缺省值和上限，`prefix_snapshots`，`max_chars`（前文上限）。

## 输入法这边（luoke-ime 改）

个人化组件拿到 `branches` 以后自己做原来主控做的事：

- 截：碰到标点（输入法自己的标点表）就截在标点前；超过字数上限就退回上一个 token 的边界（不在词中间断）；空的、开头就是标点的丢掉。
- 挑：开头的词（第一个 token）按把握排、低于门槛不给；再加最有把握的那一支的长续写。门槛、字数上限、标点表都在输入法里，随请求传的只有 `k`、`max_tokens`、`stop`。
- 本机打分进程（`scorer.py`，开发和评测用）也改成交回同样的 `branches`，两条路共用同一段挑选的代码。

## 过渡

- 旧的 `/v1/predict` 照 V1 §2 "只加不改"留着；输入法 beta1 起只用 `/v1/continue`，以后主控升约定版本时再删。
- 输入法发请求时，主控没有 `/v1/continue`（老主控，答 404）就退回旧的 `/v1/predict`，免得新输入法配老主控时没有联想。
- 两边改完，三档重跑联想评测（`engines/personal/eval_predict.py --hub`）。
